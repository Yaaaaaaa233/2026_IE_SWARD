## 3. 管道阶段与不变量

`engine.py` 按依赖顺序提供七个阶段函数，全部确定性、纯标准库：

1. `segment_events`：按 R0 契约的五条风险链合并窗（RC1–RC4 120 秒、RC5 600 秒）与场景超速 60 秒近邻（CR06）并段；结果门编码（11803/11804）不进入分档；段代表=最强证据（severity 最大、并列取最早）。
2. `eb_smooth_rate`：经验贝叶斯平滑，先验只在折内估计（`fold_prior_rate`）。
3. `fit_bins`：分位切档 → 箱风险=箱内标签均值 → 加权 PAVA 单调（风险随分位不降）→ 相邻等风险压缩。
4. `aggregate_group_deduction`：组内最大单项 + fraction×其余均值（边际递减）。
5. `fit_ruleset` / `score_vehicle`：折内学习、冻结后逐车评分并产出逐条扣分台账。

由构造保证、由测试断言的三个不变量：

- **单调性**：减少危险证据，安全分不降（EB 平滑、PAVA、边际递减均单调）；
- **可复算**：`recompute_score_from_ledger` 只用类级台账重新聚合即可精确复现分数；
- **值域**：分数恒在 [0, 100]。

## 4. 三份输出契约

| 输出 | 消费方 | 形式 | 约束 |
| --- | --- | --- | --- |
| 评分行 | T2-R4 `evaluate_scores.py` | `build_scores_rows` → gpsno / y / safety_score / fold / rule_recomputed_score | 复算差超过容差即 evaluation 硬检查失败 |
| 适配器载荷 | T2-R2 `dynamic_score.py` | `build_adapter_payload` → event_id / event_time / base_deduction / review_status + days[].exposure | 违反 R1→R2 合同（事件晚于 as_of、有效扣分落在零暴露日、事件无日记录、版本号为空）即抛错 |
| 扣分台账 | 报告与追溯验收 | ledger 逐条：gpsno / 小类 / 证据段 / 率 / 档 / 分值 / 规则版本 | 追溯率 100%；台账聚合复算=发布分 |

事件级 `base_deduction` 采用**等分摊约定**：类扣分在其证据段间均摊，摊分记录进台账——这是让 R2 时间衰减层可逐事件复算的最小约定，若②引擎另有分摊口径，数据阶段对照后升版本条。
