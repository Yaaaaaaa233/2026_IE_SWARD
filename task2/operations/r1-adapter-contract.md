# R1 → R2 对接合同

R2 不读取 R1 的分箱、单调曲线、权重或组内聚合参数。每条准备进入动态层的证据只需提供：

| 字段 | 类型 | 含义 |
|---|---|---|
| `event_id` | 字符串 | 在本次评分版本内唯一的事件段标识 |
| `event_time` | ISO-8601 时间 | 已完成时区对齐的事件段代表时间 |
| `base_deduction` | 非负数 | R1 按冻结规则算出的基础扣分 |
| `review_status` | 枚举 | `valid`、`pending` 或 `exempt` |

车辆层还需提供：

| 字段 | 含义 |
|---|---|
| `gpsno` | 唯一评价单元 |
| `initial_score` | 进入动态层前的基准安全分 |
| `initial_score_is_previous_valid` | 该分数是否来自上一有效观察期；否则无暴露时回到保守先验 |
| `upstream_score_version` | R1 规则版本，真实联调时必须非空 |
| `days[].date` | 评分序列中的自然日 |
| `days[].exposure` | 当日统一暴露单位；零表示停驶或无有效暴露 |

约束：

1. 事件时间必须属于已有日记录，不能晚于 `as_of_date`。
2. 有效扣分不能出现在零暴露日；出现时停止运行并回查分母或事件对齐。
3. 同一车辆的日期必须递增且唯一，事件标识必须唯一。
4. R1 更换暴露分母或基础规则后必须升版 `upstream_score_version`，不得静默沿用旧动态参数。
5. R2 输出保留事件的挂起、豁免和自动转有效状态，便于逐条复算。
