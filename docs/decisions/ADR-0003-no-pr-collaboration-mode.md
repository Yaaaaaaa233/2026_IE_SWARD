# ADR-0003 协作模式切换：取消强制 PR，改为协调者定期监督

- 状态：Accepted
- 决策人：叶安（仓库建立与纪律管理）
- 日期：2026-09-21
- 任务：[GOV-003](../tasks/GOV-003.json)
- 执行：ZCode agent（按叶安（纪律管理）授权整理与落地）

## 背景

比赛提交截止 2026-10-15，时间紧。既有流程要求"任务分支 + PR 评审 + 合并"，在五人分工、写入范围不重叠的现状下，PR 等待评审成为进度摩擦而非质量收益。原始数据经硬盘传递，不经 Git，数据分发不受本决策影响。

## 决策

1. **取消强制 PR**：任务登记后可直接提交并推送 `main`，不再要求开 PR 等待评审。一次任务一个分支仍推荐（便于回溯与放弃），但合并由执行者自行完成。
2. **保留三项轻量纪律**（监督的眼睛，不可省）：
   - 开工前：任务 JSON 登记（actor / owner / write_scope / branch / 依赖）；
   - 收工前：`python tools/check_governance.py` 与单元测试通过才推送；
   - 收工后：worklog 交接简报（做了什么/验证/限制/下一步）。
3. **评审改为协调者定期监督**：叶安按节奏（建议每日或每个工作日段）运行 `bash tools/supervise.sh`，一键获得近期提交、治理检查、单测结果与任务索引核对；发现越界写入、检查失败或无登记提交，在监督记录中登记并向责任人回溯。
4. **公共文件协调**：状态页、各索引、公共契约等多人共写文件，改动前在群里知会，尽量由协调者归并；发生冲突由协调者裁定归属。
5. **不变的边界**：DATA_POLICY 数据边界、结果诚实、`accepted` 仍需真实复核人、AI 开工协议与每步三文档纪律（roadmap_requirements §2）不受本决策放宽。

## 备选与取舍

- 维持 PR 评审：门禁最强，但与当前进度优先的赛况冲突，不采用。
- 完全不登记不交接：最快，但监督失去抓手、事后无法回溯谁在何时改了什么，不采用。
- 仅 CI 把关：CI 只能查机器可查项，查不到越权写入与未登记工作，作为监督的补充而非替代。

## 影响

- 挂起的 PR #5（GOV-002）与 PR #3（MODEL-002）已按本模式直接合入 main 收尾；此后新工作不再开 PR。
- AGENTS.md、COLLABORATION.md 同步修订；`tools/supervise.sh` 新增。
- 风险与接受：失去逐 PR 人工门禁，误推或越界写入由"任务登记 + worklog + 定期监督 + CI"四层补偿；叶安（纪律管理）明确接受该权衡以换取进度。
