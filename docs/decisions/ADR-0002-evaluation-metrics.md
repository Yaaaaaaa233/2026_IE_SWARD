# ADR-0002 评价指标与基线比较口径提议

- 状态：Proposed
- 提议日期：2026-09-20
- 任务：[EVAL-001](../tasks/EVAL-001.json)
- 执行者：Codex，按用户直接请求整理并提交评价指标
- 人类决策人及接受日期：待确认，未代签

## 背景

仓库已有数据契约草案与验收规范，但尚未集中定义 MOE/MOP 对应关系、主辅指标公式、Top-K 选择、概率质量、配对比较与判优边界。不同实现若采用不同 AP、分母、阈值或折外统计方式，容易得到不可比较的结论。

## 提议

以[评价指标与基线比较方案 v0.1](../plans/评价指标与基线对照方案（MOE与MOP）.md)作为待评审的集中定义：任务一保留官方 ROC AUC 主指标，建议 AP、Recall@20% 与 Brier 为核心辅助；任务二围绕官方四项评审维度提供内部证据。本文档负责计算与比较语义，[ACCEPTANCE.md](../ACCEPTANCE.md)继续负责报告形式、图表和证据要求。

通过训练内部选择、外层评估、车辆级配对比较、时间成熟检查与预登记门槛区分开发期改善和独立验证。固定管理名额与概率阈值分开，离线预测效能与真实事故减少分开。公共文档只含方法和明确标注的合成算例。

## 备选与取舍

- 只报 AUC：与官方排序直接对应，但不足以说明有限名额收益、概率可信度和运营可用性。
- 将全部技术指标加权为总分：容易掩盖尺度、方向和权重依据，且不同于官方评分，不采用。
- 用 Accuracy 或固定绝对 AUC 作为唯一门槛：不能充分反映不平衡标签下的识别价值，也缺少本项目依据，不采用。

## 影响与迁移

本次仅提出文档方案，不改变数据字段、标签、现有实现、官方 30/40 天未决口径或模型路线。当前不宣布已有实验失效，也不宣称团队已接受该协议。数据契约草案是语义参考，不作为已接受的依赖。

未来接受或修订时，应记录真实决策人、日期、冻结版本、资源与判优门槛，并登记使用旧指标或旧切分的实验清单。需要新旧口径重算时保留两个版本，不能覆盖历史记录。真实统计与预测结果继续留在受控目录。
