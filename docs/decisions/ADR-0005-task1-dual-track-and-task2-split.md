## 背景

提交截止 2026-10-15。任务一的数据清洗线与特征线主干已交付（清洗契约 v4、特征 F0、F1 管线代码），冻结基线与配对判据已立（[ADR-0004](ADR-0004-baseline-freeze.md)）。剩余优化窗口集中，而任务二（评委四维度打分、文档质量权重高）需要尽早投入人力。纪律管理线（叶安）裁定收缩任务一执行面：周航正、娄澜的任务一工作冻结，任务一剩余工作移交叶安、王健祺双人并行；另外三人转任务二。

名册更正（2026-09-22）：王健祺＝组长；叶安＝仓库建立与纪律管理；成员＝周航正、娄澜、吴钊同（GitHub 账号 wzt-ai，即 bf9425f 推送账号）。历史文档中"叶安（组长）"系称谓错误，随本批一并修正，仅改称谓不改各决策实质内容；组长对既有决策如有异议，按 ADR 流程重审。

## 决策

1. **人员与范围变更（2026-09-22 起）**：周航正、娄澜的任务一工作冻结。其已交付物（清洗契约 v0–v4、F0 `model_input.csv`、F1 管线代码）作为共享底座继续被**只读消费**，不再要求二人迭代。任务一剩余全部工作由叶安、王健祺并行执行。
2. **双人竞优模式**：两人各自独立优化（方向自定），共用同一底座与同一裁决器：
   - 底座＝冻结车辆五折（指纹见 [EVAL-001 v1.0 §6.3](../plans/评价指标与基线对照方案（MOE与MOP）.md)）＋冻结基线（随机森林，随采纳演进）＋统一评估协议（`models/task1_baselines.py` 的 OOF 协议与车辆级配对 bootstrap）。
   - 裁决＝ADR-0004 判据不放松：对当前基线配对区间下界 > 0 且点估计 ΔAUC > 0 才可采纳；**双方均过门时取区间下界更高者**；采纳即基线棘轮前进，双方在新基线上继续；未过门一方按负结果登记，不丢弃。
   - 双方每轮实验的 OOF 预测与配对区间必须落各自受控 `outputs/<task-id>/`，供裁决复算；公开仓库只登记身份、版本、指纹与判据结果（过门/未过门）。
3. **write_scope 隔离**：叶安线＝`feature_engineering/`（含 F2 及后续新增子目录）＋特征侧文档＋`outputs/`；王健祺线＝`models/`（含 `solution_b/`）＋模型侧文档＋`outputs/`。**公共冻结件**＝评估器与配对评估语义、`model_input` 契约 schema、折分表、公共索引与状态页——竞优期间任何改动须新 ADR，由纪律管理（叶安）归并。
4. **任务二三人纪律**（周航正、娄澜、吴钊同——GitHub 账号 wzt-ai＝吴钊同，bf9425f 责任人按账号归属登记为吴钊同，待本人确认）：
   - 沿用 ADR-0003 的任务登记、worklog、收工检查三项纪律与 DATA_POLICY；真实统计不入公开仓库。
   - write_scope 隔离：建议 `task2/` 代码目录与 `docs/plans/task2-*` 文档；不改任务一公共件。
   - 对任务一底座**只读消费并登记版本指纹**（sha256）；任务一产物一旦被任务二消费，其 schema 字段冻结，后续只增列不改列，保证向后兼容。
   - 评分框架内部变更走任务登记即可；涉及公共契约变更时升级为 ADR。
5. **冻结的善后**：
   - FEAT-002（F1 代码发布）的 review 状态由接手人通过"F1 真实运行＋配对评估"完成验收，证据记入后续 FEAT-003。
   - 娄澜遗留三项：IMU 行数两套口径对数并入叶安侧 F2 前置探针一并核查；校验报告 ×3 计数 bug 与清洗脚本未入库降级为**提交物可复现债**，由纪律管理（叶安）在提交打包（阶段 4）前统一处置（本人一次性交付或登记为已知限制）。

## 备选与取舍

- 维持五人分工推进任务一：清洗/特征主干已到边际收益递减区，且任务二文档权重更高，不采用。
- 双人分工协作单线（一人特征一人模型不竞争）：并行度低、缺同题对照；竞优多耗算力，但当前样本规模下单人实验成本低、裁决器已冻结可复算，采用竞优。
- 全组五人转任务二：任务一无人收口、提交物主件无人负责，不采用。
