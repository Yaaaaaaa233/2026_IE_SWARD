## 背景与参考

多人、设备和不同 agent 需要共享可靠状态，而算法路线仍在讨论。参考项目 [26isip_Aerospace](https://github.com/Zhoucmd6/26isip_Aerospace) 在提交 `a842d2cc2b1996420a1fc6d3069f11489553c0c4` 下的 AGENTS、文档导航、协作／署名、worklog、evidence 和 ADR-003。

采用的是其治理思路，未复制算法代码、项目成员名单或业务结论：唯一事实来源、状态与历史分离、真实署名、分层验收及有界问题关闭。

## 本次建立

1. 统一 AGENTS 入口，兼容文件仅重定向；不依赖某一客户端的隐藏记忆。
2. 当前状态、任务、决策、接口、证据、交接各自承担单一职责。
3. 一任务一分支与独立工作目录，认领与写入范围可追踪。
4. 提供阶段可视化验收合同，明确“实现、效果、证据、环境”分层。
5. Python 标准库治理检查和 CI 不需要比赛数据，支持多设备运行。
6. 公开仓库只共享允许公开的文件；比赛数据和派生报告默认本地。

## 当前不决定

不冻结 M0—M3 技术路线、标签期限、模型类型、机器学习依赖、成员职责和正式数值门槛；不修改 GitHub 可见性、分支保护或团队权限。

## 取舍与后续

避免照搬成熟项目的全部治理文件和复杂运行机制；先建立足够用的入口、模板与检查。任务登记不是分布式锁，CI 不是数据授权审查，状态页不是实验事实的替代品。

团队确认后记录实际采纳者与日期；需要调整可直接提出具体修改。算法路线用后续独立 ADR 接受，不因本记录的接受而自动冻结。
