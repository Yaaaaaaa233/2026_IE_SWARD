## 1 一阶段清洗规则（单类型体检，产出 v0/v1/v2）

一阶段只看**每类数据自己**是否合法，不跨数据类型比对。全部规则只打标记、做字段级处置，**永不删行、永不删车**。

### 1.3b 规则设定原因（为什么这么定）

**窗口与隔离类**

- **A1/T5/I5 窗口 [2026-06-01, 2026-07-31)**：赛题的观测窗。7/31 官方口径存疑（当天仍产数据），故整日隔离另存“待官方答复”，而不是擅自删除——等答复后并入或弃用都可逆。
- **A2 精确去重保留首条**：完全相同的行是采集/入库重复，保留一条即可表达事实；删除其余不损失信息。
- **A9 160–200 km/h 保留原值只标记**：民用车辆超 160 已极可疑，但超速执法记录、传感器毛刺、真实飙车都存在；没有外部证据时不可断定无效，保留+标记是信息量最大的选择。

**坐标类**

- **A3 缺失置空**：null 是“不知道”的准确表达，任何猜测值都会污染后续空间统计。
- **A4 (0,0) 置空**：(0,0) 在几内亚湾，是定位失败时芯片输出的占位符，不是真实位置——这是行业通病，直接保留会污染地图。
- **A5 越界置空**：物理上不可能的坐标（如经度 1058），保留会破坏任何距离/包围盒计算。
- **v2 坐标填充用“该车有效坐标中位数”且必须落在本车轨迹包围盒内**：车辆活动范围高度稳定（通勤/园区），中位数是该车的最佳位置先验；包围盒校验防止把先验错的车填充进去。填充仅用于事件表（事件的位置用于空间特征），**轨迹坐标不填充**——轨迹本身是位置先验的来源，用其中位数自填充是循环污染。
- **T3 轨迹坐标不填充（与事件不同的原因）**：轨迹 5.3 亿行里坏坐标仅 745 行（十万分之一），填充收益极低而污染风险更高。

**速度类**

- **A6/T1/I1/I2 缺失置空**：速度没有真值先验字段（无法从本行其他列推导），任何填充都是编造。
- **A7 负速度置空**：速度物理上非负，负值必是传感器错误。
- **A8 >200 km/h 置空**：赛事车辆为商用车，200 km/h 超过物理可能，判定为传感器脉冲错误。
- **I1/I2 IMU 双通道分别标记而不互填**：EMS 与 GPS 速度是同一设备的两条独立链路，互填会把“一路坏了”伪装成“两路都好”，掩盖设备故障——保留 null + 补丁清单交付分析结论。
- **T4 运行时长矛盾标记**：speed>5 而 run_time=0 在物理上矛盾，是轨迹伪造/错位的特征，但不排除采样异常，故只标记。

**IMU 特有**

- **I3 加速度合模长 <0.1 或 >5.0（g）**：静止传感器噪声约 0.02–0.1 g，5 g 相当于剧烈碰撞；长期静止读数说明传感器“装死”。
- **I4 日期矛盾标记**：data_time 与 data_date 不一致说明入库/传输错位，常伴随数据错行。

**派生表**

- **三种事件计数并存（raw/segments30/days_flag）**：不同建模口径需要不同粒度（报警频率 vs 独立事件 vs 活跃天数），提前并存避免下游重算。
- **标签窗口 6/21 起**：前 20 天（6/1–6/21）留作特征窗，后 40 天作标签窗，是“用过去 20 天预测未来 40 天风险”的赛题设定。
- **splits 分层 5 折**：正类样本稀缺（126/500），随机分折会导致某些折正类过少；按标签分层的哈希折保证每折 25–26 台且可复现。

### 1.4 派生表规则（vehicle_day / features / labels / splits）

- `evt_raw_count`（原始条数）/ `evt_segments30`（同类型 30 秒内并段后的段数）/ `evt_days_flag` 三种事件计数口径并存；
- `quality_flags`：`imu_not_observed`（有轨迹无 IMU）、`not_observed`；
- 标签：窗口内 11803/11804 且 start_time ≥ 2026-06-21 记正类 → **126 台正类车 / 222 条记录**，清洗前后守恒；
- splits：车辆级按标签分层 5 折（每折正类 25–26 台），哈希确定可复现。

## 2 二阶段清洗规则（跨类型互证，产出 v3/v4）

二阶段把**事件、轨迹、IMU**按“车辆+时间”对齐，检验它们相互之间是否讲同一个故事。样例验证：6 台车、1,390 万 IMU 行、600 万轨迹行、6.2 万事件。原则：**只产标记与可信度，不产删除**。

| # | 规则 | 跨类型关系 | 判定条件 | 标注位置 | 典型可信度 |
|----|----|----|----|----|----|
| C1′ | 行驶状态持续矛盾 | IMU 与 轨迹 | IMU 速度 >20 km/h **且**前后 ±60s 轨迹全部 <5 km/h（逐点矛盾不算，只抓持续矛盾） | `imu_traj_persistent_conflicts.csv`（人工复核短名单） | 70–89 比较异常 |
| C2 | 速度量级矛盾 | IMU EMS 与 轨迹速度 | \|差\| >30 km/h 且持续 ≥30s | 并入 C1′ 清单 | 70–89 |
| C3 | 传感器死区 | IMU 自身 与 轨迹 | 轨迹 ≥20 km/h 的 60s 窗内，加速度合矢量与陀螺方差同时近零 | `imu_dead_windows.csv`（窗级） | 90+ 十分异常（该窗不可信） |
| C4 | 事件坐标-轨迹空间一致性 | 事件 与 轨迹 | 事件坐标（v2 填充后）落在本车 60 天轨迹包围盒外，或 ±5min 无轨迹点 | 事件表新列 `xtype_coord_flag` | 见 §4 打分 |
| C5 | 行车类事件-静止矛盾 | 事件 与 轨迹 | 30xxx/11401 事件时刻轨迹 speed<5 且 distance=0 | 事件表新列 `xtype_motion_flag` | 70–89 |
| C6 | 停车类事件-行驶矛盾 | 事件 与 轨迹 | 60292 事件时刻轨迹速度 >10 | 事件表新列 `xtype_motion_flag` | 70–89 |
| C7 | 覆盖缺口 | IMU 有无 与 轨迹行驶 | 有轨迹行驶记录的日期 IMU 全天无记录 | `coverage_calendar_marked.csv`（日级 `imu_gap_day`） | 覆盖事实，非错误 |

### 2a 二阶段规则设定原因（为什么用跨类型互证）

- **为什么需要二阶段**：一阶段只验证“单条数据自身是否合法”，查不出“合法但说谎”的数据。样例中的经度 15.41 在合法区间内（A5 放行），但该车轨迹全在东经 114–115——只有把事件和轨迹对齐才能发现这是“丢首位”的坏值。单类型规则对这类错误是盲的。
- **C1′ 只抓“持续矛盾”、放过 8 万条逐点矛盾的原因**：停车-起步瞬间，3 秒采样的轨迹点会取到速度 0 的点，而 2 秒采样的 IMU 记录到减速尾流——这是采样时差的正常物理现象。逐点比对会把正常驾驶误判为异常；加“IMU >20 km/h 且 ±60s 轨迹全程 <5”的持续判据后，8.3 万条收敛为 61 条真矛盾，误报率从 3% 降到千万分之七。
- **C3 用“轨迹确认在行驶”作为死区前提**：IMU 读数静止有两种可能——车真停了（正常）或传感器装死（异常）。用轨迹速度 ≥20 km/h 排除“车停了”的可能，才能把死区从正常停车中分离出来。
- **C4 用“轨迹包围盒”而非固定半径的原因**：固定 1 km 半径会误伤跨城/长干线行驶的车辆；每车 60 天轨迹的分位包围盒刻画的是该车自己的活动范围，是事件位置的个性化先验（并留 ±0.5° 容差防误伤）。
- **C4 命中后在 v3 置 null 而不恢复原值**：合法区间内的错值（丢首位）比缺失更危险——缺失可被模型容忍，错值会把事件钉到错误的地理位置。按“v3=标注+null”口径处理，v4 再评估填充。
- **C5/C6 的价值**：事件自带的速度字段与轨迹速度是独立来源，二者吻合是事件表可信度的旁证（样例 6.2 万条仅 1 条矛盾）。
- **C7 是覆盖事实而非错误**：官方 2.0 说明明确“小部分车辆 IMU 不覆盖所有时段属正常”。缺口日的行为特征置缺失，**不能**当作安全驾驶的证据，也不能因缺口剔除该车。

**二阶段的重要纪律**（样例验证的核心发现）：正类事故样本车辆A 同时踩中三条规则（(0,0) 坐标的事故、33 天 IMU 缺口、4 个死区窗），但它是真实正类样本——**任何“数据难看就剔除”的操作都会删掉真实事故**，所以二阶段一切输出都是标记与可信度，处置权留给建模阶段。

### 2b null 填充可行性分析（v2/v4 的核心步骤，2026-09-19 口径更新）

版本语义：**v1/v3 = 标注并用 null 填充；v2/v4 = 在 v1/v3 基础上分析每个 null 能否用有效值填充——有合理方案则填充，无合理方案则保留 null；两种情况都保留 v1/v3 的标记列。** 逐字段分析结论如下（脚本与本文档同步维护）：

| 置空字段 | 阶段 | 有无合理填充方案 | 方案与依据 | 处置 |
|----|----|----|----|----|
| 事件坐标（A4/A5 置空） | 一阶段 | **有** | 该车有效事件坐标中位数，且填充值必须落在本车轨迹包围盒内，否则弃填 | v2 填充（738 条） |
| 事件坐标（C4 置空） | 二阶段 | **有** | 同上（中位数 + 包围盒校验）；若中位数仍出包围盒则弃填 | v4 填充或弃填保留 null |
| 事件速度 | 一阶段 | 无（单类型） | 事件系统速度无同源先验 | v2 保留 null |
| 事件速度 | 二阶段 | **有（跨类型）** | 事件时刻匹配的轨迹点实测速度（独立传感器，±5min 内） | v4 填充并标记 speed_filled_from_traj；无匹配点保留 null |
| 轨迹坐标 | — | 无 | 轨迹本身是位置先验的来源，用其中位数自填充等于循环污染 | 保留 null |
| 轨迹速度/航向/时长/距离 | — | 无 | 无同源或跨源真值 | 保留 null |
| IMU ems/gps 速度 | — | 无真值先验字段 | **保留 null（既定口径）**；同秒另一通道的冗余值以“填充补丁汇总”交付供参考，不改数据 | 保留 null + 补丁汇总 |
| IMU 加速度/陀螺 | — | 无 | 无真值先验 | 保留 null |
| C3 死区窗内读数 | 二阶段 | 无 | 传感器行驶中未记录（非字段缺失），无法外推恢复 | 保留原值 + 窗级标记 |
| C7 缺口日 | 二阶段 | 无 | 数据不存在 | 该日特征置缺失 + 日级标记 |

传感流的填充分析以 `sensor_fill_patches/imu_fill_patch_summary.csv`（车×日汇总：可由同秒另一通道冗余填充的行数与示例）交付，不复制 130 GB 分片。

## 3 v0–v4 五个版本的定义与区别

| 版本 | 目录 | 内容定义 | 传感流物理副本 |
|----|----|----|----|
| **v0_interface** | `v0_interface/` | 符合契约接口的**原样转换版**：仅字段名/主键/类型转换（`event_time→start_time` 等），原值保留（含坏值），**无任何标记列**——“符合接口的数据” | 有（全量） |
| **v1_annotated** | `v1_annotated/` | **一阶段标注版**：A/T/I 系列规则命中的字段置空 + 全部标记列，行不删——“标注异常值版” | 有（全量） |
| **v2_corrected** | `v2_corrected/` | **一阶段填充版**：在 v1 基础上逐字段分析 null 的可填充性（§2b），有合理方案的填充（事件坐标中位数，须过轨迹包围盒校验），无合理方案的保留 null；标记列全保留——“null 分析填充版” | 无（=v1，差异仅 745/5.3 亿行） |
| **v3_anomaly_marked** | `v3_anomaly_marked/` | **二阶段标注版**：在 v2 基础上叠加跨类型标记（表加 `xtype_coord_flag`/`xtype_motion_flag` 列；C4 命中的坐标按 v3 语义置 null；传感流出 C1′/C3/C7 三个窗级/日级标记清单）——“跨类型互证标注版” | 清单（窗级/日级） |
| **v4_assessed** | `v4_assessed/` | **二阶段填充+可信度版**：在 v3 基础上对 null 做填充分析（§2b：C4 坐标中位数填充、事件速度可由匹配轨迹速度填充、其余保留 null），对每条标记给出 `disposition`（处置）+ `confidence`（0–100）+ `grade`（三级），全部标记保留——“可直接供建模使用的终版” | 清单（含可信度） |

五版**行数完全相同**（铁律：清洗前后标签行数与正类车数守恒），区别只在“值是否修正、带几层标记、可信度如何”。

## 4 同一条记录在五个版本中的形态（真实样例，已脱敏）

以下均为真实数据实例（样例车以代号车辆A/B/C/D 表示，车辆A 即样例验证中的正类事故样本；坐标截断至两位小数）。

### 实例 1：正常事件（占 99.98%）

    源数据   : 车辆D | 30.52… | 114.85… | 30017 长时间压线 | 56 km/h | 2026-06-24 21:41:57
    v0       : evt_00000001,车辆D,30017,长时间压线,2026-06-24 21:41:57,56,30.52…,114.85…,(空),(空),2.0
    v1       : …,56.0,30.52…,114.85…,ok,ok,2.0
    v2       : 与 v1 完全相同（没有可修正的问题）
    v3       : …,ok,ok,2.0, xtype_coord_flag=ok, xtype_motion_flag=ok
    v4       : 与 v3 相同（无标记即无处置；confidence 列=100 或空）

### 实例 2：(0,0) 占位坐标的事故（C4 + A4 双命中，标签必须保住）

    源数据   : 车辆A | 0 | 0 | 11803 疑似事故 | — | 2026-07-11 06:32:33     ← 真实事故，坐标是占位符
    v0       : 原样保留 lat=0,lng=0（无标记）
    v1       : lat="",lng="", coord_flag=zero_placeholder           ← 值置空，行保留
    v2       : lat=30.52…,lng=114.85…（该车有效坐标中位数）, coord_flag=zero_placeholder  ← 填充，标记保留
    v3       : 同 v2 + xtype_coord_flag=ok（填充点已落回本车轨迹包围盒）
    v4       : 同 v3 + disposition=coord_filled_median, confidence=95, grade=十分异常(坐标)
               → 含义：坐标值原本十分异常（95 分确认是占位符），但事件本身按时间+类型可信，标签保留

### 实例 3：经度疑似丢首位（只有二阶段能抓到）

    源数据   : 车辆B | 30.57… | 15.41… | 30017 | 2026-07-…

    二阶段 C4: 该车 60 天轨迹经度全在 114–115 → 事件坐标在包围盒外

    v4       : disposition=keep_and_flag（保留原值仅标记）, confidence=75, grade=比较异常
               → 不自动改成 115.41（存在其他可能），交给人工/建模判断

### 实例 4：经度物理越界（一阶段即可修）

    源数据   : 车辆B | 39.27… | 1058.08 | 30017

### 实例 5：IMU 与轨迹持续矛盾（C1′，人工复核短名单）

    逐点矛盾（8.3 万条/样例，停车-起步边界计时差）: 不进任何清单，不标注，不清洗
    持续矛盾（61 条/样例，IMU 报 >20km/h 而前后 ±60s 轨迹全程 <5km/h）:

### 实例 6：传感器死区窗（C3）

    轨迹以 ≥20km/h 行驶的 60s 窗内 IMU 加速度/陀螺方差同时近零（9 窗/样例，车辆A 占 4）:

### 实例 7：IMU 全天缺口（C7，覆盖事实而非错误）
