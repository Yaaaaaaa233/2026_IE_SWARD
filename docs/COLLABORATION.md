# 跨成员、设备与 agent 协作

## 1. 新设备启动

```sh
git clone git@github.com:Yaaaaaaa233/2026_IE_SWARD.git
cd 2026_IE_SWARD
pip install -r requirements.txt
python tools/check_governance.py
python -m unittest discover -s tests -v
```

SSH 使用个人已有配置，不复制私钥进仓库。上述命令需治理分支合入后才能从默认分支取得；合入前从对应 PR 分支检出。检查器仅用 Python 3.10+ 标准库；`tests/` 单测允许使用 [requirements.txt](../requirements.txt) 登记的第三方依赖，CI 安装同一清单后运行（GOV-006）。新增依赖先登记再提交，未登记依赖的测试会在 CI 失败。

复制 [本地配置模板](../configs/local.example.toml) 为 `configs/local.toml`，填写本机数据与输出目录。模板目前用于约定位置；尚无数据管线自动读取，后续实现必须遵守该契约。算法环境和锁文件由相应实现任务选择，不在治理初始化时预设。

## 2. 新会话给 agent 的启动提示

> 先读 AGENTS.md、docs/DEVELOPMENT_STATUS.md 和本次任务记录。报告当前分支、已有改动、写入范围、依赖与验收计划。只执行本任务；保留他人改动。不得把未验证假设当作结论，数据与真实结果默认不提交到公开仓库。结束时提交检查证据和简短交接。

Codex、ZCode、DSH 不需要共享对话历史或私有记忆。共享 Git 中的规则、任务、决策和交接即可。不要假设不同客户端都会自动加载同名规则文件；在客户端可持久化的项目提示里指向 `AGENTS.md`，避免复制正文形成多个版本。

## 3. 任务认领与并行

1. 先查看最新远端任务记录和开放 PR；每个任务一个 JSON 文件，按 [任务约定](tasks/README.md) 填写。
2. 每个成员／agent 使用独立分支与工作目录。分支建议 `work/<task-id>-<topic>`；本次初始化使用 `chore/agent-governance`。
3. 认领应明确 `actor`、`owner`、`write_scope`、`branch` 和基准提交，并通过共享分支／PR 让其他成员看见。仅写在本地不构成跨设备互斥锁。
4. 任务写入范围重叠时先协调，拆分文件或明确一个归并者。不要让多个 agent 同时编辑主状态页、公共配置或评估协议。
5. 任务记录不是分布式锁；离线认领或并发提交仍可能冲突。真正动手前重新检查远端，冲突时由任务协调者确定归属。
6. 用户直接交付的当前任务可先执行不冲突的工作并补登记，不增加无意义的二次许可步骤。

可用独立 clone，或在已干净的仓库中创建 worktree：

```sh
git fetch origin
git worktree add -b work/TASK-ID-topic ../ie-TASK-ID origin/main
```

已有未提交改动时先辨认来源，不自动 `reset --hard`、`clean`、stash 或把所有文件一并提交。跨设备通过 Git 同步代码和允许共享的文档，数据通过授权渠道单独同步。

## 4. 提交与集成（2026-09-21 起无 PR 模式，见 [ADR-0003](decisions/ADR-0003-no-pr-collaboration-mode.md)）

- 小而明确的提交；使用显式文件清单暂存，不默认 `git add .`。
- 暂存后运行 `python tools/check_governance.py --scope index`，它读取暂存版本，避免工作目录修好了但提交仍是旧内容。
- **不再要求 PR**：任务登记后直接提交并推送 `main`；一次任务一个分支仍推荐（便于回溯与放弃），合并由执行者自行完成。不重写他人历史、不强推他人分支、不改变仓库可见性。
- 公共文件（状态页、各索引、公共契约）改动前在群里知会，尽量由协调者归并；冲突由协调者裁定归属。
- 治理检查与单元测试通过才推送；单测第三方依赖统一登记在 requirements.txt（CI 与本地同口径安装），检查器本身保持仅标准库。模型或公共契约变化需要对应验收，文档检查通过不能替代算法验收。
- 实现者将任务置为 `review`；`accepted` 需要实际复核者、日期和证据。没有复核人时保留待复核，不能虚构签名。
- 评审由协调者定期执行：`bash tools/supervise.sh` 一键输出近期提交、治理检查、单测结果与任务索引核对；越界写入、检查失败或无登记提交登记回溯。
- 自己修复后的测试与另一会话／成员的复核分开记录。发现新问题注明影响范围，不把环境、报告或模型问题混成一个结论。

## 5. 交接与署名

每次有实际改动的会话结束前按 [模板](templates/handoff.md) 新增交接：任务、分支、改动、检查、限制、下一步。只写摘要，不提交聊天导出或整段终端日志。

任务 `owner` 记录真实的人类责任人；`actor` 记录本次执行工具或人员；`reviewer` 记录实际复核者。未知填 `null` 或“待确认”，不得沿用参考项目成员名单，也不得根据 Git 账号猜测姓名。文件级贡献可集中在对应任务和交接记录，不给每个文件复制长署名表。
