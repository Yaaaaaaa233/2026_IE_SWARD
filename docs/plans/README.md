历史路线草案（v1，M0–M4 工程视角与验证驱动方法论）已并入路线图 v2 与特征线规范，原文见 Git 历史。本轮讨论得到的候选组织方式：

1. **M0 数据审计与假设清单：** 先验证数据覆盖、单位、标签与信号可测性，形成待验证问题。
2. **M1 固定评估与最小基线：** 明确时间、标签、折分与训练推理一致性，跑通简单模型与提交输出。
3. **M2 小成本验证方向：** 暴露量、时间结构、重复报警、画像、轨迹节律和 IMU 逐项对照。
4. **M3 深化有效方向：** 仅对证据支持的组投入更多工程，验证组合并收敛最终方案。
5. **任务二同步推进：** 从基线阶段建立可追溯的规则评分，随后验证风险区分与运营边界。

治理规则、任务模板、路径约定和证据规范可以先实施，不需要提前决定以上每个算法方向。不要因目录中出现 M0—M3 就认为团队已通过该路线。
