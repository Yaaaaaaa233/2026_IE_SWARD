# FEAT-014：叶安线特征与模型持续迭代探索方案

版本：v0.1；日期：2026-09-26。负责人：叶安；执行：Codex（按用户指示启动）；任务：[FEAT-014](../tasks/FEAT-014.json)。方案文本已提交，当前从 E0 开始执行；新实验及其结果只记入受控输出。

## 1. 这轮要做什么

在叶安线已经使用的评定标准下，开展一轮有预算的连续探索：**看已有模型错在哪里 → 提出特征或算法假设 → 跑一小批对照 → 保留有用信息 → 根据结果设计下一批**。目标是把已有较丰富的特征真正用好，同时允许补充有明确用途的新特征，争取提高开发期风险排序效果。

FEAT-012/013 主要做了已有 F3 列组的删减、几种模型配方、随机种子及固定融合。本轮进一步开放特征重新表达、模型与特征组合适配、误差驱动的新特征，以及根据上一轮结果调整下一轮方向。不能把“重复试了很多参数”当成新信息探索，也不要求先重新提取整套原始数据。

借鉴王健祺 [MODEL-008 迭代记录](../experience/task1/03_冲刺版本迭代总表.md) 的工作方式：不同信息组分别建模、按误报／漏报修正、弱单模保留互补机会、逐版记录正负结果。它提供候选思路，其版本成绩和最优配方不直接成为叶安线结论。

本方案沿用 FEAT-012 的任务内探索安排，**不把 EVAL-001 正式推广到全项目作为开工前置**，不要求王健祺、吴钊同先停工对齐。本轮也不修改他们的代码或评定方式。

## 3. 探索范围和优先顺序

优先发挥已有特征的优势：先修正表达与算法适配，再做针对性的新信息提取。下面是候选库，非必须逐项跑完的固定网格。

| 方向 | 具体做法与可检验假设 | 起始对照和停下来的依据 |
| --- | --- | --- |
| G0 现有特征重新组织 | 全 F3、已有精简夜间视角、历史事件视角分别适配模型；检查近重复、稀疏列和强相关族。仅从训练折拟合相关性筛列、缺失处理与缩放。假设更多特征的优势被冗余或模型容量遮住 | 固定模型比较列组，固定列组比较模型；已有配置直接复用有效 OOF，不重算充数 |
| G1 暴露量归一化与事件语义 | 在可见窗口内计算每活跃日／每有效行驶小时的事件率；可靠里程可用时才算每千公里事件率；事故、未遂、急操作分别保留频次、涉及日期数、最近发生间隔。原始计数和分母同时保留 | 对照是同组未归一化特征；检验高活动车辆误报是否减少。没有可靠分母就停该分支，不能以采样点数冒充里程 |
| G2 时间变化与规律 | 从车辆×日面板提取最近 3/7/14 日及全窗的事件率、活跃程度、间隔、趋势、波动；检查末周相对前期变化、夜间事件占比相对夜间暴露量 | 先选少量有语义的趋势与持续性指标，与全窗统计比较；不枚举全部窗口×全部统计量。缺记录与真实零活动区分 |
| G3 场景与同类车辆偏差 | 利用可见轨迹／事件建立活动强度×夜间、历史事件×暴露量等少量交互；可选训练折聚类或相对训练折同群均值的偏差 | 先做人工有意义的交互，再考虑聚类；聚类中心、群均值、缩放只从训练折学习。不恢复已排除的未来画像字段 |
| G4 质量与稀疏观测适配 | 复用既有 IMU／轨迹特征，增加覆盖量、可靠性标记；区分“没有事件”“没有记录”“设备不足”。可试向量模长／分位数等已有原始数据能支持的稳健表达 | 对照固定行为特征加／不加质量信息；若收益只来自观测量代理且机制不明，标记条件性候选；不把缺 IMU 的车辆移出评估 |

每个新特征须写清：业务含义、来源、时间范围、单位、分母、缺失语义、是否需要训练折拟合、对应假设、预计最终 61 天能否构建。缺资料的特征先标 `blocked`，继续其他路线。

输入默认使用 FEAT-009 v2 Y1 F3、FEAT-011 列台账及相关可见期事件／车辆日表；已有受控中间表够用就不重新扫描全量原始数据。确需新增提取时新建输入版本和缓存，不能覆盖 F3 原表。旧 FEAT-012 加载器只支持已锁定 F3，不能直接放宽列白名单后宣称新特征已审计。

### 算法适配库

- **EBM**：复用 A/C 的平滑配置；在适合的列组尝试少量交互、叶节点样本量／分箱调整。交互选择只能在训练折进行；先比较不带交互版本。
- **随机森林、HistGradientBoosting**：对精简语义／归一化／交互视角重新适配，不因此前在全 F3 上落后就直接淘汰，也不为全量高维表无界加深树。
- **带正则的逻辑回归**：检验重表达后是否少量线性信号已足够，也作为不同误差模式的潜在成员；填补、编码、标准化均折内拟合。
- **LightGBM**：环境可修复且成本合适时加入小叶数、强正则候选。依赖缺失记环境问题，先隔离环境修复／烟雾测试，不让整轮等待该模型。新增依赖另登记，避免改坏共享环境。
- **融合**：优先简单均值或预定 logit 权重，少量不同信息成员优先于同类模型堆叠。学习权重／校准／stacking 必须用外层训练集内部 OOF；不能把全体外折 OOF 的标签拿来训练后又报告同一 OOF 的分数为有效外折效果。

对某列组做自动参数搜索时，每个外折只在其训练部分用三折选型；每次最多四个预登记配方。不同固定配方也可各自生成探索 OOF，但每版都计入预算。不能把大量隐藏搜索称为一个版本。

## 4. 第一批怎么跑，以及后续如何改变方向

E0 先锁定旧结果和输入，复现 F3 EBM-A；已有合格 OOF 可作为其他历史对照，不重训所有历史版本。首批 E1 最多六个新版本，默认种子 42：

| 版位 | 特征与算法 | 主要回答的问题 |
| --- | --- | --- |
| V001 | 全 F3 + 折内正则选择的逻辑回归 | 现有丰富特征经正则后是否能用更简单方法捕获有效信息？ |
| V002 | 已有精简夜间视角 + 与历史 full RF 相同配方 | RF 此前落后是否与输入冗余有关？ |
| V003 | 同一精简视角 + 与历史 full HGB 相同配方 | boosting 对精简视角是否比全量更合适？ |
| V004 | 全 F3 EBM-C + 最多 5 个折内选择的二阶交互 | 特征已有，缺的是变量间组合关系吗？ |
| V005 | 精简视角 EBM-C + 同样交互机制 | 交互在精简输入下是否更有用？ |
| V006 | 历史视角 EBM-A + G1 小组新增特征 | 暴露量归一化／事件语义是否补充原有计数？ |

训练前展开并锁定继承配置的全部有效参数，不能仅写“默认参数”。V001 的四个 C 候选拟为 `{0.01,0.1,1,10}`，三折选择发生在各外折训练内；其余继承配置由输入锁定阶段提取。G1 字段和分母先审计再锁定；若数据不足，V006 延后，不能临时用未来画像补齐。运行失败保留失败版号，不悄悄替换。

第一批不要求占满六版再分析；每 3–6 个完整版本组成一批。后续遵循以下规则，可按反馈重排 G1–G4 的优先级：

| 上一批观察 | 下一批优先尝试 | 必须保留的归因对照 |
| --- | --- | --- |
| 某列组明显更适合树模型或线性模型 | 沿该组做小范围容量／正则适配 | 输入不变，只改模型；随后再改特征 |
| 全量模型受少数稀疏或重复族影响 | 合并同义列、删冗余、调平滑 | 同算法、同种子，完整组与精简组 |
| Top100 误报集中在高活动／夜间暴露车辆 | G1 事件率及 G3 暴露量交互 | 原始计数版与加入率／交互版 |
| 漏报车辆总量不高但近期变化明显 | G2 时间趋势与事件持续性 | 同模型的全窗统计版与趋势增补版 |
| IMU 稀疏群表现差且覆盖差异明显 | G4 质量标记、覆盖收缩／缺失表达 | 同行为信息、不同质量处理 |
| 单模分数一般，但能纠正强模型的不同错误 | 与稳定强成员做少量固定融合 | 每个单成员及同权重融合；报告纠正和新增错误 |
| 多个同类版本错误几乎相同 | 换信息组或模型家族 | 保留旧组作为参照，停止只换种子刷最高分 |

误差分析使用完整 OOF，展示 Top100 的误报、漏报、排名变化及分群人数。它用来形成下一批假设；不能据此把某些车辆的验证标签编码成特征，或按全体 OOF 错误名单为这些车辆专设训练权重。类别权重等仅能依赖当前训练折的信息。

每个版本训练前写三句话：**为什么试、相对谁只改了什么、什么结果会继续／放弃**；训练后追加结论。确需同时改特征和算法的复合版本，至少保留可拆解的父版本，或明示本版无法单独归因，下一批安排关键消融。

## 5. 阶段执行、机器与可视化验收

所有阶段负责人均为叶安，执行 agent 在批次记录署名。E1/E2 是同一探索阶段内的小循环：本方案获确认并授权执行后，可在范围和预算内连续推进，不逐版本等人工确认；机器失败只暂停受影响分支。人工复核集中在最终报告，不虚填中间 `accepted`。这延续用户已明确的连续探索工作方式；方案本次仍是待复核草稿。

下列命令按方案逐步实现；本次已实现 E0 `run.py prepare`、E1 `run.py batch` 及 E0/E1 `audit.py`，后续 E2／E3 命令仍待实现。每个命令失败须非零退出，结果落可解析 JSON。`<local-config>` 配置受控输入、输出和运行预算；`<run-dir>` 是全新运行目录。

### FEAT-014-E0：锁定输入、对照及可复用证据

- **目的／依赖**：依赖 FEAT-009 v2 真实输入、RF/F3 OOF、FEAT-012/013 结果及 FEAT-011 列台账；确保接下来每版能与过去比较。它们是产物依赖，不要求修改原任务人工复核状态。
- **操作／产物**：核对来源、实际文件与协议；记录旧版本完整排名和错误摘要；构建新输入登记方式；运行 F3 EBM-A 复现；产出 `input_lock.json`、`anchors/`、`historical_ledger.json`、环境清单及基准复现报告。
- **机器验收**：拟 `python3 feature_engineering/experiments/feat014/run.py prepare --config <local-config>`；拟 `python3 feature_engineering/experiments/feat014/audit.py --run-dir <run-dir> --stage E0`。车辆键唯一、标签／折号／窗口与锁定表逐行相等、参照预测完整且在 `[0,1]`；同环境 EBM-A 复现概率最大绝对差 `≤1e-10`，否则调查依赖或浮点差异，不能悄悄换对照；历史其他 OOF 只在来源与配置核验后复用。
- **坏例**：重复样本、少一车、篡改一个折号、错误锚点或指纹均必须被拒绝。
- **可视化验收**：A0 时间轴＋三个参照的关系图；A1 输入族与来源覆盖表。建议通过标准：能看出模型用的过去和标签的未来；RF、固定 F3、滚动探索冠军不混用；排除字段和缺资料处明确标出。
- **放行**：机器通过后进入 E1；来源不明的新增数据隔离，不为此暂停已核验的原 F3 路线。

### FEAT-014-E1：特征表达与模型适配的滚动小批次

- **目的／依赖**：依赖 E0，先把现有特征优势转化为可检验模型收益，再逐步补新信息。
- **操作／产物**：按第 4 节选 3–6 版，先写 `batches/Bxxx/plan.json` 与列字典，锁定后构建特征及训练。产出每版配置、特征清单、五折 OOF、折内审计、指标和失败记录。每批结束回填决策后才能追加下一批，禁止事后改原计划。
- **机器验收**：拟 `python3 feature_engineering/experiments/feat014/run.py batch --config <local-config> --batch B001`；拟 `python3 feature_engineering/experiments/feat014/audit.py --run-dir <run-dir> --stage E1`。每车恰一次 OOF；五折齐全；训练验证互斥；所有拟合器、筛列器和内层选型只见当前训练车辆；`y/fold/gpsno/sample_id/版本字段` 不作为模型特征；不调用会恢复未审计画像的旧加载捷径。
- **新特征断言**：N1 汇总计数等于逐文件计数；N2 输入−隔离−去重=输出，车辆和标签不变；N3 主键唯一；N4 逐文件 SHA-256 及交付 MD5 可复核；N6 截止时点后事件不入特征。事件计数与分母有明细回溯，零分母不产生无穷值；训练折拟合数据行指纹留存。
- **坏例／N5**：注入未来事件必须被过滤或拒绝；打乱外折验证标签不改变该折预测／选择／变换器；修改验证协变量不改变训练所得统计和选列（验证预测可改变）；重复连接必须失败。检查本身先在合成数据验证。
- **可视化验收**：B0 版本路线图，连接“父版本→改动→结果”；B1 固定 F3 对照的 AUC 差异和区间图，辅以 RF、父版本比较表；B2 耗时—效果图。建议通过标准：一眼看出哪种改动有效、代价多少；全部完成版本和失败状态可找到，不能只展示冠军。
- **放行**：合法完整的版本进入 E2 分析；坏 OOF 不进排行榜；合法负结果可以指导下一批，不要求每版过判优门。

### FEAT-014-E2：误差反馈、互补融合与定向再试

- **目的／依赖**：依赖至少一批 E1，回答“下一步试什么”，避免无反馈地穷举。
- **操作／产物**：检查高风险名单误报、漏报及可解释分群；计算预测相关性和错误重叠，提出下一批假设。保留少量有互补性的单模，用最多三个不同信息成员构造简单融合；新特征或模型继续回 E1，融合也登记独立版号。
- **机器验收**：拟 `python3 feature_engineering/experiments/feat014/run.py diagnose --config <local-config>`；拟 `python3 feature_engineering/experiments/feat014/audit.py --run-dir <run-dir> --stage E2`。误报／漏报与冻结标签、Top100 定义可复算；分组带人数与正类数；所有融合键、折号相同；权重、logit 截断常数在本版训练／组合前锁定。学习融合器必须有外折训练内部 OOF 证据，不能直接拟合已见全体 OOF 标签。
- **坏例**：成员 OOF 缺车／错位、成员标签不一致、融合读入外折验证标签都应被拒绝。
- **可视化验收**：C0 错误类型×信息组热图；C1 风险前 100 名的“纠正了多少、又新增多少错误”变化图；C2 单模与融合并排比较。建议通过标准：能讲清继续某方向的理由；小群体只作线索，不能凭少量车辆宣称规律；相关性低不等于融合必然提升。
- **放行**：第 6 节预算内回 E1 或进入 E3；最多连续三个同一假设的变体无父版本改善、也无已验证组合收益时，暂停该分支。

### FEAT-014-E3：候选收口、稳定性检查与交接

- **目的／依赖**：依赖全部有效版本与预算记录；形成可复现的候选结论，不只报最高单次分数。
- **操作／产物**：对最多两条有前景的单模路线补种子 7/2026，种子 42 已有结果直接复用；每条产生预先约定的三种子平均，所用概率／logit 规则先锁定。独立从保存 OOF 复算指标及对照差异；挑选最多三个身份明确的候选：最高探索点估计、较稳定候选、低成本备选，允许重合。产出一页报告、全版本台账、复现命令、最终窗口适配清单与回退指针。
- **机器验收**：拟 `python3 feature_engineering/experiments/feat014/run.py finalize --config <local-config>`；拟 `python3 feature_engineering/experiments/feat014/audit.py --run-dir <run-dir> --stage E3`。独立指标复算误差 `≤1e-12`；输入输出指纹一致；候选的配置、代码和数据版本可追溯；固定环境复跑检查不能通过换种子取代。报告相对 RF 和 F3 的原有判优门、辅助门、实测裕量及波动；裕量不足三倍已知复现抖动标记骑线待复验，种子跨度另列而不当作独立置信区间。
- **坏例**：篡改指标表或混入别的 run 图表必须被审计发现；不完整候选不能生成“完整通过”。
- **可视化验收**：D0 全版本迭代曲线，区分单版成绩与历史最高包络；D1 候选三种子分布及平均；D2 固定对照增益区间和辅助指标门；D3 最终候选的特征族消融或已有可归因对照摘要。建议通过标准：最高一次与稳定表现分开，能看到失败和负结果，知道为何保留／放弃某方案。
- **放行**：完成后任务置 `review`，由叶安实际复核再登记 `accepted`；机器通过、效果不足可以同时成立，不伪造采纳。超出预算／改标签／改折分／改窗口另记方案变更。

## 6. 预算、继续条件和停止条件

- **首轮预算：最多 30 个新评估版本**。建议 18 个特征／模型版本、6 个误差驱动或固定融合版本、6 个稳定性版本；其中最后 6 个优先留给两条路线各两个新增种子及一版种子平均。前两类可互相调剂，记录原因。
- 一个完整五折 OOF 算一版；一个新权重／成员组合算一版；每个种子单独算一版，种子平均也算一版。历史 OOF 导入不算新版本；E0 对照复现单列并计入计算耗时。失败尝试保留版号和耗时，最多额外 10 次失败重试，不能无限失败重开。
- 内层搜索候选最多四个，五外折×三内折的实际拟合次数完整记录，不能借“一版”掩盖无界搜索。单版先估计耗时，预计超过 60 分钟则先简化或改排期，不直接挂大网格。
- 自正式开跑起第一轮以 **24 小时墙钟上限**和 30 版上限先到者收口；前 18 小时探索，后 6 小时保留给稳定性、审计和报告。收到更早交付时间则提前收口，主动保留交付余量。每约 6 小时写一次受控进度快照，进度不需要等用户回复才继续。
- 连续两批既无新点估计最好版本，也无确认的互补融合收益／可执行新假设，就停止扩展；某分支连续三个合理变体均无上述价值就换方向。时间到了不能为凑满 30 版继续跑。
- 增益区间跨零不是预算内探索的停止条件；数据时点泄漏、折分漂移、来源不可核验则停止受影响分支并修复，违规版本不进入合法排行榜。

不设保证达到的 AUC 目标。可能结论包括：新的特征表达有效；已有特征主要缺算法适配；单模改善有限但互补融合有用；或本轮没有可靠增益。负结果仍留下复用特征、适配经验和明确回退方案。
