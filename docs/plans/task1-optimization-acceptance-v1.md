# 任务一优化验收规程 v1（机器 + 人工关键数据 + 可视化）

状态：Accepted（v1.0，2026-09-22，[ADR-0005](../decisions/ADR-0005-task1-dual-track-and-task2-split.md)）
配套方案：[task1-optimization-plan-v1](task1-optimization-plan-v1.md)
维护人：叶安。本规程与验收记录中的真实数据派生统计一律落 git 忽略目录，公开仓库只登记规程与结论。

## 1. 验收框架

三层验收，两个时点：

| 层 | 内容 | 时点 | 执行人 |
| --- | --- | --- | --- |
| L1 机器验收 | 治理／复现／契约／防泄漏／配对评估五类自动检查 | 每任务收工自检（推送前） | 执行者（人或 agent） |
| L2 人工关键数据验收 | 对真实数据派生产物按抽样规程核对关键数字 | review → accepted 之间 | 复核人（另一成员或组长王健祺） |
| L3 可视化验收 | 按图清单人工判读，通过标准成文 | review → accepted 之间 | 复核人（组长王健祺为主，可委托） |

规则：L1 不过不得推送；L2/L3 任一不过不得置 `accepted`，退回登记问题；验收证据（图路径＋核对记录）落受控 `outputs/acceptance/<task-id>.md`，公开任务 JSON 只登记"已验收＋复核人＋日期＋结论"。双线竞优（ADR-0005）双方产物适用同一规程。

## 2. L1 机器验收（每任务必跑）

1. **治理**：`python tools/check_governance.py --scope index` PASS（读暂存版本）；任务 JSON 字段完整（actor/owner/write_scope/branch/基准提交）。
2. **单测与 CI**：`python -m unittest discover -s tests -v` 全绿；远端 CI 三平台绿。新增第三方依赖先登记 requirements.txt。
3. **管线合成测试**：涉及 `feature_engineering/` 改动的任务，加跑 `pytest feature_engineering/tests`（窗口边界与标签窗排除断言必须在内）；新增特征模块必须附带合成数据测试（无真实数据可跑的防泄漏断言）。
4. **复现一致性**：受控输出重跑两次——纯统计脚本要求输出逐字节一致（时间戳除外）；含随机性管线要求固定种子下指标一致。产物 manifest（行数／列数／生成时间／代码提交号）登记受控台账，关键输入输出 sha256 登记台账。迭代轮次另需**版本登记三件套**齐全：git 提交（代码+文档）、`outputs/<task-id>/round-<N>/` 轮次目录（OOF 预测、配对区间、manifest）、受控台账迭代登记行（版本号→代码提交→输入指纹→对当时基线的结果→过门与否）——缺一即 L1 不过。
5. **契约校验**：`model_input` 类产物过 schema 硬检查——sample_id 唯一、每车一行、y∈{0,1}、fold 完整、y/fold/窗口与版本元数据不入特征；事件表主键唯一、时刻落在特征窗内（标签窗事件不得出现在特征聚合，由合成测试覆盖断言）。
6. **配对评估**：候选版本由统一评估器产出 OOF 预测与车辆级配对 bootstrap 区间（PREREG：2,000 次／95%／种子 42），落 `outputs/<task-id>/`；判据执行结果（过门/未过门＋辅助容差 Recall@K、Brier）写入任务 notes 与受控台账。

## 3. L2 人工关键数据验收（按产物类型的抽样规程）

复核人按下表抽样核对，通过标准＝抽样无一不符；不符时暂停验收、登记问题、执行者修复后重抽。

| 产物 | 抽样规程 | 核对内容与通过标准 |
| --- | --- | --- |
| F1 真实运行（FEAT-003） | 抽 10 辆车（含历史险情车与无事件车） | 从 `events_clean` 人工数特征窗内事故/未遂/合计计数，与 `f1_prior_*` 特征逐车一致；历史险情车总数与受控台账口径一致 |
| F2 对齐（FEAT-004） | 抽 5–10 辆，**必含方向异常车** | 对齐后前向/横向/垂直分量分布物理合理（重力轴集中、前向均值显著大于横向）；对齐参数随能源类型无异常跳变 |
| F2 六场景事件表 | 抽 10 个 IMU 事件 | 类型定义与计算逻辑一致（人工读代码＋看原始窗段）；抽 3 个急刹事件与轨迹速度突降时刻对齐 |
| F2 ×官方事件交叉 | 抽 10 个疑似碰撞事件 | 与官方碰撞预警族时间邻近记录核对，命中率登记为**相对校准信号**（明确不宣称检测准确率） |
| 消融与裁决数字 | 每次采纳/裁决 | 受控台账登记数字＝脚本输出；双线裁决数字由双人各自复算一致 |
| 语义复核 | 每个新特征族 | 特征命名词义与计算逻辑一致（人工读代码＋抽样取值验证），单调方向与语义先验一致或登记例外原因 |

## 4. L3 可视化验收（图清单与通过标准）

图统一落 `outputs/figures/<task-id>/`（git 忽略）。通过标准＝与受控台账数字一致、无下述病态；不达标退回；"负结果"类不达标（如无相关）登记后放行，不阻塞。

| 组 | 图 | 通过标准 |
| --- | --- | --- |
| A 基线与候选诊断 | OOF 校准曲线（可靠性图）、分折 ROC/PR、Top-K 命中曲线、分数分布分段箱线（安静/无 IMU/方向异常等缺口段） | 校准曲线无系统性狂飘；折间差异与噪声底一致（单折不讲故事）；分段图与误差剖析台账一致 |
| B 新特征质量 | 新特征按 y 分组分布、缺失模式图、语义单调性散点 | 无意外双峰/常数列；缺失模式与覆盖口径一致；单调方向符合语义先验或登记例外 |
| C F2 对齐 | 对齐前后三分量散点/热图、方向异常车修复前后对比 | 对齐后重力轴集中、前向方差显著大于横向；异常车修复效果可见或登记失败名单 |
| D 事件交叉 | 每车 IMU 事件率 vs 官方事件率散点、时间对齐命中分布 | 呈正相关则登记强度；无相关登记为负结果放行 |
| E 竞优裁决 | 双线 OOF 分数差分布、ΔAUC 配对区间图 | 与裁决复算数字一致；区间跨零情况如实呈现 |
| F 任务二联动 | 评分分布、维度扣分构成堆积图 | 与任务二线消费的底座版本指纹一致 |

## 5. 任务 × 验收矩阵

| 任务 | L1 | L2 | L3 |
| --- | --- | --- | --- |
| FEAT-003 F1 运行＋探针 | 全项（含 pytest 合成测试） | F1 抽样核对；探针数据抽样复核 | A＋B（F1 特征）＋D（如含交叉） |
| 迭代轮次（双线 FEAT-/MODEL- 各任务，含 F2 主管线、事件语义二批、模型侧实验等） | 全项＋版本登记三件套齐全；涉事件表加契约校验 | 轻量口径：本轮改动直接相关的 1–2 项抽样（改对齐→对齐规程；新增事件特征→语义复核；涉 IMU 事件→交叉规程）；裁决相关轮次加"数字双人复算" | 本轮产物对应组图（B/C/D 按改动类型）；**拟提交的终候选版本**须在人工推进门前补全完整 L2/L3 |
| EVAL-003 终评 | 全项＋双线人工宣告留痕（宣告人/日期入任务 notes） | 裁决数字双人复算＋台账对账（含迭代登记表与版本史一致性） | A＋E＋F |
| TASK-006 提交打包 | 治理＋单测＋CI＋产物存在性与格式校验 | 提交物与受控数字一致；可复现走查（新环境拉库重跑一遍关键产物） | F＋说明文档图表与受控数字一致 |

迭代轮次的 L2/L3 采用轻量口径（每轮只验本轮改动直接相关的项），完整 L2/L3 收口在两个时点：任一版本被**采纳为基线**时（该版本升级为共享底座，须补全），以及人工推进门前（双线各自的终候选版本）。

## 6. 验收记录与归档

- 每次验收在 `outputs/acceptance/<task-id>.md` 记录：日期、验收人、三层各项结论、抽样明细、发现的问题与处置。
- 公开仓库任务 JSON 的 `accepted` 登记：复核人真实姓名＋日期＋证据指针（worklog 或受控记录的位置说明，不携带真实数值）。
- 纠纷处理：双线对裁决或验收结论有异议时，以冻结评估器复算结果为最终依据（ADR-0005 §2），复核人现场见证。
