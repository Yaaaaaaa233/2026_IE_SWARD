# 任务一双基线执行方案

## 1. 目标与边界

本方案为任务一建立两个可复现基线：L2 正则化逻辑回归与随机森林。模型读取统一的 `model_input.csv`，使用冻结车辆五折产生折外预测，并按任务一评价方案报告 ROC AUC、AP、Recall@20%、Brier、Log Loss 及 Top K 指标。

当前实现沿用数据线已经落地的 20/40 代理回测口径：每台车使用预测截点前 20 天特征，标签为截点后 40 天内是否发生事故或未遂事故。20/40 描述特征窗与标签窗，不是训练集与验证集的划分。训练与验证在形成车辆级样本后再按冻结车辆折号进行。

本轮结果属于开发期内部 OOF 回测，不是独立测试集成绩，也不构成跨月份时间外推证据。正式比赛口径以后续赛题澄清和团队接受的 ADR 为准。

## 2. 数据接口

模型默认读取本地特征工程交付的 `artifacts/model_interface/model_input.csv`。若该文件不存在，可从契约目录的 `features.csv`、`labels.csv` 与 `splits.csv` 连接生成输入。

硬检查包括：

- `sample_id` 唯一；
- 每辆车一行；
- `y` 仅为 0 或 1；
- `fold` 完整；
- `y`、`fold`、窗口字段及版本字段不进入模型特征。

缺失值填补、数值标准化和类别编码全部封装在模型流水线中，仅在相应训练部分拟合，外层验证折不参与拟合或调参。

## 3. 模型配置

| 模型 | 固定配置 | 内层候选参数 |
| --- | --- | --- |
| L2 逻辑回归 | `solver=lbfgs`，`max_iter=2000`；数值中位数填补、缺失指示、标准化；类别众数填补与独热编码 | `C` 为 0.1、1、10 |
| 随机森林 | 300 棵树，`max_features=sqrt`；数值中位数填补、缺失指示；类别众数填补与独热编码 | `max_depth` 为 4、6、无限制；`min_samples_leaf` 为 5、10 |

两类模型均不使用类别权重和过采样。随机种子默认为 42。

## 4. 验证协议

外层使用数据交付中的冻结车辆五折。每轮用四折训练、一折验证，使每台车恰好获得一次来自未见过该车的模型预测。模型超参数只在外层训练部分内部使用分层三折选择，评分指标为 ROC AUC。

最终报告合并 OOF 指标与各折 AUC。合并 OOF AUC 与各折 AUC 平均值含义不同，必须分别命名。若没有独立保留集，应统一称为“内部五折 OOF 结果”，不得称为最终测试成绩。

## 5. 运行方式

在仓库根目录执行：

```powershell
$env:FEATURE_ROOT = "<本地特征工程根目录>"
python models/task1_baselines.py
```

也可以显式指定输入与输出：

```powershell
python models/task1_baselines.py `
  --model-input "<model_input.csv>" `
  --output-dir "<受控输出目录>"
```

本地输出包括 `task1_baseline_metrics.json` 与 `task1_baseline_oof_predictions.csv`。两者包含真实比赛数据派生信息，按[数据政策](../DATA_POLICY.md)保存在受控本地目录，不提交到公开 GitHub。

## 6. 判读与后续

两个基线必须在相同车辆、标签、折分和特征版本上比较。优先查看 ROC AUC，同时检查 AP、Recall@20%、Brier、Log Loss 和各折稳定性。当前基线用于建立最低可复现参照；后续特征或模型升级应复用同一评估器，并保存配对 OOF 预测以支持车辆级配对比较。
