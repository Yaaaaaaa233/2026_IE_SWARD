# FEAT-009：0923 新口径下叶安线特征与模型适配执行方案

状态：**方案已确认入库；执行仍冻结**（[ADR-0008](../decisions/ADR-0008-feat-009-protocol-v2-route.md)）。版本 v1.0，2026-09-24。负责人和方案复核人：叶安；执行 agent 待认领；跨线 OOF 交付由王健祺线自行登记。本文件是 [FEAT-009](../tasks/FEAT-009.json) 的新协议重启方案。叶安确认“入库吧”仅接受本方案的路线、机器验收与人工可视化规则，**不解除**该任务的 `blocked` 状态，也不授权运行真实模型。旧版[建模优化方案](feat-009-feature-modeling-proposal.md)保留历史身份。每步实际开工仍须先完成该步前置样张、人工核查及 Git 同步。

## 1. 目标、边界与当前依据

目标是在 [ADR-0006](../decisions/ADR-0006-official-qa-foundation.md)、[ADR-0007](../decisions/ADR-0007-near-miss-count-unit.md) 下，先形成**时间可见、逐车对齐、可同折比较**的 F1/F3 输入，再验证现有特征能否通过模型适配改善任务一风险排序。只把代理回测中的有效 OOF 当开发期证据，不把它称作官方未来 40 天成绩。

- 主开发协议暂沿用 `[2026-06-01, 2026-06-21)` 20 天特征窗与 `[2026-06-21, 2026-07-31)` 40 天代理标签窗；这不是官方对特征长度的限制。`as_of`、时区、左闭右开边界与数据版本必须随产物登记。新版代理标签／车辆五折由[公共生成任务](../tasks/EVAL-003.json)在受控目录 `outputs/protocol_20260923/label_v2_record_proxy/` 生成，目前仍待数据／评估负责人复核。代理标签只按 `11803≥1` 或有效 `11804≥2`，未遂逐条计次；特征期历史险情可以作为特征，但标签期险情绝不能作为特征。
- 官方允许最终预测使用 6 月 1 日至 7 月 31 日全部 61 天历史。当前数据内没有与“8 月 1 日截点、完整 61 天特征、其后 40 天标签”同构且标签完整的训练样本；不得把含代理标签窗的信息加入特征，或把 61 天模型的旧代理 AUC 写成同口径验证。主判定使用训练与验证截点一致的特征定义；61 天利用方案如要研究，另立假设和验证设计。
- 本方案不改王健祺线 `models/` 代码，不替其确定 V5 重跑方向。新版 V5 OOF 是正式跨线比较的外部依赖；在它就绪前，可完成叶安线的特征审计、输入重建、合成测试和预登记。
- 8 月 1 日正式推理的端到端检查放在模型定型后执行一次；若随后更改最终管线再重跑。它不阻塞当前特征与模型适配。

## 2. 执行顺序与阶段门

每一步按 [roadmap 编写要求](roadmap_requirements.md)先确认方案、机器验收和可视化验收，再改代码、生成真实结果。真实数据、指纹、逐车预测、图表和统计只放受控目录；公开 Git 仅保存代码、合成测试、无真实数值的规则与交接。下文列出的新检查入口均为**拟实现入口**，未实现前不得写成已通过。

### FEAT-009-V2-Y0：字段来源与时间可见性审计（`not_run`）

- **目的／依赖**：先证明 6 月 21 日能看到哪些输入，避免用新标签重跑一套仍有未来信息的特征。负责人叶安；依赖 ADR-0006/0007 和现有 F1/F3 源码、字段字典，不等新版 V5。
- **具体操作**：对 F0→F1→F2→F3 的实际候选列建立字段来源表，逐列登记原始表、统计起止、计算窗口、上游依赖、折内拟合范围和处置（保留／按截点重算／代理回测排除）。至少覆盖画像 8 个动态原列、F3 画像偏差列、以 `highway_ratio` 为群键的同群列；审查 F3 原始新特征表、基座、筛列前后模型输入及综合分的依赖链，查明 `f2_prior_incident_x_night` 等画像交互是否实际入模。按 `energy_type` 的原始定义核查它是否确为截点前已知静态字段。独立核对深夜研究桶与官方时段字段的命名。产出受控 `outputs/feat-009/v2/y0/visibility.csv`、`issues.json`、来源说明和图；每行记录 `feature,source,source_end,as_of,parents,fit_scope,decision,reason`。
- **机器验收**：拟实现 `python feature_engineering/experiments/task1_feature_modeling/check_visibility.py --config <local-config>`；断言候选列集合与来源表集合完全相同，每列的所有上游最终可追到原始源与统计截止，任何 `source_end > as_of` 的动态原列及派生列均不处于“保留”，事件时间 `>=as_of` 的列不可用，`y/fold` 与版本元数据均不入特征。列数守恒：候选数＝保留＋重算＋排除＋待查，且待查数必须为 0 才能放行。构造未来画像原列、由其派生的列、缺来源列及 `y` 伪装特征四类坏输入，各自必须使检查非零退出。真实字段数和指纹只写受控报告。
- **可视化验收**：一页字段来源矩阵与依赖流向图，标记特征截止、画像统计终点、代理标签窗和每类处理决定；图上注明时区、窗口和“深夜／官方夜间”的不同定义。图必须让不读代码的复核人指出任一红色未来字段如何传到最终候选，未闭合依赖单独列数。叶安抽查全部画像原列及至少两条派生链（画像偏差、同群键）；任一解释与底表不符则退回。
- **放行**：字段清单、处置和坏输入拒绝测试经复核，才能开始 Y1；未知来源不得默认为可用。阶段结果为 `review`，未经人工核查不写 `accepted`。

### FEAT-009-V2-Y1：重建时间一致的 F0/F1/F3 新版输入（`not_run`）

- **目的／依赖**：让 RF 锚点、F1、F3 和后续 V5 在同一新标签、同一新折分和同一预测截点下可比。依赖 Y0 处置表及公共新版标签／折分复核；无需等待 V5。
- **具体操作**：先在独立受控目录复制公共标签／折分版本并按键重绑定，旧 F0/F1/F3 产物保持不变；按 Y0 来源表重算或排除无权使用的列，生成干净的 F0 代理基座，再由它构建带新 `feature_version`、`label_version`、`split_version` 的 F1 与 F3 代理输入及清单。历史事件、IMU、轨迹只用 `[as_of-20d, as_of)`；不能证明截点前可见的画像动态列及偏差、交互、同群派生列一律排除。若 `highway_ratio` 无法按截点重建，Y1 默认**停用它参与的群键及派生列**；如要改用仅静态 `energy_type` 分群，先另记方法变更和合成测试，不把它混同于旧 F3。将无标签筛列、同群统计、填补和编码的拟合移到每个训练折内；原始候选表不预先按全体样本筛列。F3 的 23:00–05:00 特征按“深夜”登记；新增官方夜间 21:00–06:00 并行特征须另预登记，不能静默改旧列含义。
- **机器验收**：拟实现 `python feature_engineering/experiments/task1_feature_modeling/check_v2_inputs.py --config <local-config>`；断言 500 个唯一车辆／样本、F0/F1/F3 与**复核后的公共**标签／折分按 `sample_id,gpsno` 逐车一致，标签规则、版本及输入输出指纹齐全，五折每折双类且每车恰一折，`y/fold` 与版本字段未入特征，Y0 排除列及其派生列不在候选，历史事件／轨迹时间严格早于 `as_of`，新旧目录绝不覆盖。守恒检查：公共目标车辆集合＝F0 集合＝F1 集合＝F3 集合＝新版标签集合＝折分集合。合成负向测试覆盖标签窗事件误入、旧 `y/fold` 混入、画像原列及派生列漏删、重复／缺失车辆、未来时刻、折内拟合见到验证样本，并分别要求非零退出；重复运行的确定性部分逐字节一致（时间戳除外）。
- **可视化验收**：同一 run ID 导出“特征窗—标签窗—画像终点”时间图、F1/F3 特征族保留／排除图、缺失与覆盖图及五折类别分布图。图中标版本、样本量、时间和单位；类别数、车辆明细与真实图只留受控目录。复核人抽查 10 辆车的历史险情计数，含单次未遂、重复未遂和无险情例；再抽查画像衍生列及 21:00、23:00、05:00、06:00 边界的深夜／官方夜间分桶。任何未来列或标签窗事件被保留即退回，不以图形好看放行。
- **放行**：机器验收和人工来源抽查通过后，将新版输入固定为 Y2/Y3 的唯一代理输入；旧 F1/F3 效果不迁移，新版特征底座也不因“能生成”就自动采纳。

### FEAT-009-V2-Y2：新协议对照与模型预登记（`not_run`）

- **目的／依赖**：先重建唯一公共锚点并冻结本线模型选择，之后才看新版效果。依赖 Y1 通过、EVAL-001 正式升版和统一评估器；V5 的新版 OOF 由王健祺线负责提供，本线只读核对。
- **具体操作**：评估负责人在 **Y1 时间可见的 F0 基座**和新版协议上重跑并登记 [ADR-0004](../decisions/ADR-0004-baseline-freeze.md) 定义的 RF（300 棵，`max_features=sqrt`，深度 `{4,6,None}` 与叶数 `{5,10}` 折内选，种子 42）；旧 RF OOF 和旧画像 F0 不得代用。王健祺线若交付新版 V5，核对其训练特征、标签、折分、OOF 与环境；只有经新版统一判据采纳，才作为 FEAT-009 主对照。若 V5 未就绪，主比较与时间预算保持冻结；需改对照时先经任务与评估版本修订。对原四候选做合成冒烟和各训练折类数检查；对照线可按公共规则审核自身 OOF，但叶安线的选型池、随机种子、运行预算、辅助门槛必须在读取**叶安线新版候选 OOF 效果**前封存。拟沿用如下**待复核候选**；若因类数或成本需更改，先修方案与任务，不在试跑后增删。

  | 候选 | 固定参数；其余使用任务环境登记默认值 |
  | --- | --- |
  | EBM-A / EBM-B | `interactions=0 / 5`，`max_bins=64`，`min_samples_leaf=10` |
  | LightGBM-A | `num_leaves=4`，`min_data_in_leaf=30` |
  | LightGBM-B | `num_leaves=8`，`min_data_in_leaf=40` |

  两个 LightGBM 均拟用 `learning_rate=0.05`、`n_estimators=200`、`reg_lambda=1`、`feature_fraction=0.8`、无单调约束。五个外折内各用三折 AUC 选候选，完全并列按表顺序；F1/F3 各独立选型。拟沿用 ADR-0004 的车辆级配对 bootstrap 2,000 次／95%／种子 42，主比较要求 ΔAUC 点估计和区间下界均 `>0`，下界 `≥0.01` 才称有实际意义；Recall@100 退化 `≤0.02`、Brier 退化 `≤0.005`。若辅助门槛因新患病率需调整，必须经评估 ADR 升版并在真实主运行前锁定，不能按结果回调。
- **机器验收**：拟扩展 `audit.py`，核对 F1/F3/RF/V5 的车辆、`y`、`fold`、窗口、标签与折分版本以及 OOF 指纹；任一不一致非零退出。检查 EVAL-001 升版记录、RF 新版登记、主对照采纳身份、候选依赖版本、每个内外折双类、配置冻结时间与运行预算；至少一个旧版 OOF／错误折号的合成输入必须被拒绝。不得用旧 V5 或旧 RF OOF 填补新版缺口。
- **可视化验收**：同一受控报告展示对照身份表、逐折类别数、候选与复杂度／预计拟合次数和时间预算；图上清楚区分“已具备可比 OOF”“待提供”“仅旧协议”三种状态。复核人不读代码也能说出唯一主对照、主指标、两条辅助容差及何时冻结。
- **放行**：叶安核查 Y1 与预登记，数据／评估负责人核查 EVAL-001 新版 RF，王健祺线自行复核新版 V5。主对照身份固定、所有指纹一致且前置样张经确认后，才把 FEAT-009 从 `blocked` 改为 `active`；否则正式主判定保持冻结。

### FEAT-009-V2-Y3：严格嵌套模型适配与一次主判定（`blocked`）

- **目的／依赖**：检验时间可见的 F3 特征经折内选型后，是否相对**Y2 已冻结的新协议主对照**增加排序信息。依赖 Y2 全部放行；旧 S0 和未提交的 `modeling.py`／`run.py` 草稿不构成放行证据。
- **具体操作**：先在合成输入上验证已有草稿的防泄漏负向测试，再沿 FEAT-009 的外层车辆五折、外层训练集内三折选择框架，对 F1 与 F3 分别运行 Y2 封存候选；所有缺失填补、筛列、同群变换、编码与选型只见相应训练子集。一个固定配置只生成一套完整 OOF；按冻结评估器对 Y2 主对照做车辆级配对 ΔAUC 与辅助指标判定。F1 对 F3、另一个非主对照、特征族与误差互补性只作预先注明的次级诊断；不因结果不利而换折、增删候选或改主比较。若运行中断，记录失败 run ID 后按相同封存配置重启，不挑有利折。
- **机器验收**：拟运行 `python feature_engineering/experiments/task1_feature_modeling/run.py --config <local-config>` 和独立 `check.py --run-dir <controlled-run>`；检查每车恰一条 OOF、预测概率有限且在 `[0,1]`、外折训练与验证互斥且五折覆盖全体，内层只见外层训练集，所有拟合器和筛列器记录训练行指纹，输入等于 Y1/Y2 锁定指纹。合成负向测试验证扰动外折验证标签不会改变训练所得变换器、候选选择或预测；扰动验证协变量不能改变训练所得筛列和群统计；反例必须失败。固定配置重跑选型、OOF 与配对判定一致；结果图、指标、底表同一 run ID。按现行有效 ADR 的配对 bootstrap 与辅助判据复算；任何中断或缺折不得生成“通过”。
- **可视化验收**：同一 run ID 输出 ΔAUC 配对区间图、逐折选择与类别数表、F1/F3 成本—效果图、特征族及误差互补图。主图标清 0 线与 `+0.01` 实际意义门槛、样本和正类数；辅助指标表写明“本线－对照”方向与容差。单折诊断不得冒充主成绩，少数正类小群不单独宣称收益；真实图与 OOF 只留受控目录。
- **放行**：无论正负结果都登记。机器通过、图表与底表一致且叶安完成真实复核后，才可将 FEAT-009 提交终评；未过门不自动展开新模型搜索。采纳仍须按双线统一评估器和人工终评纪律执行。

- **可视化验收**：一页首页放主判定图、两模型排名关系图、Top-K 重叠图及缺失／覆盖分群图；每个小群同时标车辆数和正类数，正类过少的群标“仅描述”。复核人应能从首页独立回答：结果相对哪个新协议对照、是否过零线、辅助项是否退化、哪类车是共同错误、哪些结论仍未证明。图、表、文字与同一 run ID 的机器输出逐项一致，否则退回。
- **放行**：L1 全过，L2 按[验收规程](task1-optimization-acceptance-v1.md)抽查关键数据，L3 人工图表复核，受控 `outputs/acceptance/FEAT-009.md` 有真实复核人、日期与结论后，才可将 FEAT-009 置 `accepted` 或记录负结果完成。双线终评是否启动仍由叶安、王健祺按人工推进门另行宣告；本方案与代理不代替该决定。
