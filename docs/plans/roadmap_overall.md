距提交约 25 天。倒排里程碑：M1 底座基线（本周）→ M2 特征验证 → M3 评分体系 → M4 深化文档 → M5 终检提交（10-10～10-12，留 3 天缓冲）。

## 3. 端到端管线与三段交接面（接口定义）

```text
官方数据 2.0（约 116GB，四类源，30 分片 IMU/轨迹）
   ↓ 交接面 A：数据线 → 特征线
清洗数据 v4_assessed / v1_annotated + 冻结折分
   ↓ 交接面 B：特征线 → 评估线 / 模型线
model_input.csv（F0）+ feature_schema.json + group_assignments
   ↓ 交接面 C：模型线 → 评分线 / 官方
oof_predictions（评估）· model_score（评分）· forecast_result.csv（提交）
```

每段交接面遵守同一套规则：**单一权威载体、单一 owner、主键与行数不变量、版本字段、机器可查断言**。接口字段语义变更一律走 ADR，实现代码引用版本号，不私自改语义。

| 交接面 | 生产者 → 消费者 | 权威载体 | 主键 / 不变量 | 版本字段 | 机器验收断言 | 权威文档 |
| --- | --- | --- | --- | --- | --- | --- |
| A 清洗数据 | 娄澜 → 周航正 | 契约四表：target_vehicles / events_clean / vehicle_day / labels + splits（实际载体：v4_assessed 主表 + v1_annotated IMU + 冻结折分文件） | gpsno / row_id / gpsno+date；500 车与正类车数跨版本守恒；标记不删行，隔离可对账 | source_version=2.0；v1_raw / v2_filled 双版；split_version | 守恒断言、隔离对账、schema 校验、sample_id 唯一 | 数据契约 v0.1（R0 冻结 v1.0） |
| B 模型输入 | 周航正 → 吴钊同 / 叶安 / 王健祺 | model_input.csv（500 行×特征列）+ feature_schema.json（字段字典）；车辆分组走 group_assignments，聚类标签不直接入特征 | sample_id 唯一；样本集合与 labels 一一对应；y/fold 只作元数据不入特征；特征计算不触 [as_of, as_of+H) | feature_version（F0_v1 待登记）；group_rule_version | sample_id 唯一性、标签折号完整性、防泄漏字段检查、全空/常数列排除（特征线接口已内置） | 模型契约 §1（PR #3）+ F0 特征字典 |
| C 模型输出 | 模型线 → 评分线 / 官方 | oof_predictions（折外预测，评估消费）；model_score（gpsno, prob, rank_pct, calib_flag，评分消费）；forecast_result.csv（官方三列） | 500 行全覆盖；gpsno 集合与 target_vehicles 一致；概率 ∈[0,1]；无重复；同种子复现一致 | model 命名 A/<成员>、B/<群>/<模型>；source_version / feature_version / group_rule_version | 输出合同断言；方案 B 任一车可回查群组分派、子模型版本与校准参数 | 模型契约 §3/§6（PR #3） |

当前接口的两个未对齐点（R0 / R2 处理，统一接口就是补这两件事）：

1. **features 表所有权重叠**：数据契约把 features 表划给数据线（事件聚合），实际统一特征已由特征线产出（model_input.csv）。建议契约 v1.0 冻结时把 features 表 owner 改为特征线、权威载体即 model_input.csv + feature_schema.json，数据线只产 A 面四表——一个交接面只有一个权威载体，避免两份"特征表"各改各的。
2. **接口层插补的折内纪律**：当前 model_input 构建时做了数值缺失中位数处理；中位数属学习型统计量，按红线 3 应只在训练折内估计。二选一：接口层传带缺失标记的原值、插补移入模型线折内流程；或插补统计量按折预计算并随 feature_schema 登记来源与拟合范围。R2 搭 harness 时定死并写入契约。

## 4. 不可违反的红线

1. **车辆级评估**：官方 AUC 按 500 台车计算；一切指标、折分、bootstrap 以车为单元；同车多窗口不拆折、不冒充独立样本；事件级数据只能做特征。
2. **数据守恒**：清洗永不删行删车，缺数以标记表达；隔离行可追溯、可逆；500 车与正类车数跨版本不变（变了必须能解释）。
3. **防泄漏**：特征严格早于 as_of；标签窗数据只做标签；填补/标准化/平滑/校准/路由权重一切学习型处理只在训练折内拟合；报警段合并形态不用于标签。
4. **统计量入模**：IMU/轨迹以人为约定阈值提取的统计特征入模，原始高频序列不直接进模型；阈值做敏感性试验，不交模型学习。
5. **暴露归一**：计数类特征按里程/时长归一，"跑得勤"不得被读成"危险"。
6. **口径参数化**：lookback/horizon/as_of/K 显式配置，禁止硬编码；口径变更先走 ADR。0918 会议的 40+20 与 holdout_350_150 仅作对照参数保留。
7. **数据边界**：真实统计、车辆标识、折外预测只存受控本地目录，不入公开仓库；失败结果保留，不删问题车辆制造完整。
8. **输出合同**：forecast_result.csv 三列、500 行全覆盖、概率 ∈[0,1]（predict_proba 口径）、无重复；同版本配置同种子两次运行输出一致。
9. **评估纪律**：主比较用同一折分同一非空样本集合；不挑有利折；全量折外反复用于选择后不得再声称独立证据；胜出判据须超过 3× 种子抖动。

## 9. 执行纪律与变更管理（2026-09-20 会议口径）

- **每步三文档先行**：执行任一小步前，该步的方案、机器验收规则、可视化验收规则必须齐备、经确认并落地 git，才开始执行；时序与 AI 开工协议见 [roadmap_requirements.md](roadmap_requirements.md) §2。
- **AI 开工协议**：AI 先读 AGENTS、完整路线图与纪律要求，声明当前执行路线图哪一步；发起者不逐步指挥（"双手离开键盘"），统一用"形成完整方案并遵守全部纪律与路线图"式指令。
- **git 同步**：本地每完成一个操作即提交推送远端；远端是唯一共享事实。
- **草稿不入库**：未确认的草稿发群里或给协调者，git 只进经确认的路线图、规则与回填。
- **AI 产出人工核查**：未经负责人核查的 AI 产出标"待复核"，不标记完成、不进下一步消费。
- **先路线图后代码**：路线要改先改本文件或线 roadmap；未登记的实验结果不得进入任何公开结论。
- **状态回填**：各阶段条目完成后回填勾选与实际结果；失败路径如实记录（含 not_run/blocked），不得上调状态等级；数值结论报告裕量与抖动。
- **口径与接口变更**：走 ADR + 受影响实验清单；旧口径结果不静默作废也不混用，需重算时保留两个版本。
- **真实数据与产物**：原始数据只读；清洗产物、特征、折外预测存受控本地目录并带 manifest；公开仓库只留方法、规则与合成示例。
- **验收分层**：实现/契约、实验效果、验收证据、环境依赖四维分别报告，禁止一枚总 PASS。
