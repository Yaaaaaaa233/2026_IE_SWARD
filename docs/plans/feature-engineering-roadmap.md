## 1. 一页结论

特征线已在受控本地打通“清洗数据 → IMU 事故语义特征 → 多源统一模型输入 → 无监督聚类”的完整链路，并具备 YAML 配置、命令行入口、分片调试、全量处理、模型持久化和合成数据端到端测试能力。

当前成果的定位是**可供对接和复核的工程底座**，还不是已冻结的建模基线。进入正式模型实验前仍需完成四件事：

1. 冻结数据、时间窗口、折分和特征所有权等公共口径。
2. 将接口层全局插补迁移到训练折内，消除潜在拟合泄漏。
3. 用真实事故回放校准 IMU 冲击、旋转和翻滚候选阈值。
4. 接入统一评估 harness，完成监督基线、分组消融和稳定性验证。

### 4.3 当前必须解决的接口问题

1. **特征表所有权**：数据契约草案包含 `features`，实际统一特征由特征线产出。契约 v1.0 应明确 B 面唯一权威载体及 owner，避免数据线与特征线各维护一份特征表。
2. **插补拟合边界**：当前接口实现包含数值中位数与类别缺失处理。中位数等学习型统计量必须只在训练折估计；建议 B 面输出保留缺失的原值和缺失标记，插补移入模型流水线。
3. **聚类分派边界**：探索性聚类可用于画像和假设生成；若作为方案 B 的路由或输入，聚类参数必须折内拟合，并提供稳定性、最小群规模和全局兜底规则。
4. **版本与溯源**：每次交付需同时记录 `source_version`、`feature_version`、`split_version`、时间窗、阈值、代码提交和随机种子。

## 7. 推荐执行顺序

1. **先冻结接口边界**：解决 features 所有权和折内插补，两项未解决前不把当前模型输入标为 F0。
2. **再补可追溯性**：为每列特征记录来源、窗口、单位、归一化、缺失语义、阈值和版本。
3. **校准 IMU**：用真实事故回放形成阈值敏感性报告，不用一次工程试跑直接定阈值。
4. **接统一评估器**：在相同车辆、相同折分和相同非空样本上跑监督基线与消融。
5. **冻结后再扩模型**：只有某组特征显示稳定增益后，才进入复杂组合、路由或集成。

## 9. 当前结论边界

- 可以说：特征线已在受控本地建立完整工程链路，统一接口的结构与校验已具备，已识别并处理设备方向和缺数据主导聚类等工程问题。
- 不能说：IMU 已带来稳定预测增益、聚类就是最终风险分层、阈值已经校准、模型效果已经通过比赛验收。
- 下一次状态升级需要：公共契约冻结、评估 harness 可用、真实回放校准完成、冻结五折上的监督基线与分组消融形成可复核证据。
