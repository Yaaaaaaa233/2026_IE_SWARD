# 评价指标与基线比较方案 v0.1

**状态：Proposed，待评审，尚未冻结。** 对应任务 [EVAL-001](../tasks/EVAL-001.json) 与 [ADR-0002](../decisions/ADR-0002-evaluation-metrics.md)。本文定义拟采用的评价口径，不代表已实现评估器、已运行模型或已取得实验成绩。

建议任务一以 **ROC AUC 为主指标**，以 **AP、Recall@20% 和 Brier 分数为核心辅助指标**；同时展示 Lift、概率校准、稳定性和成本。任务二采用风险区分、可解释、可运营和完整性四个维度验收。模型效果、工程检查和团队评审状态分别报告。

官方要求以仓库内的[赛题说明](../../赛题资料/赛题说明.pdf)及后续正式澄清为准：任务一按 AUC 排序；任务二由评委对各维度打分。本文不把内部辅助指标变成新的官方排名公式，也不裁决官方概述与任务详情的 30/40 天差异。

## 1. MOE 与 MOP 如何对应

- **MOE（Measure of Effectiveness，效能指标）**：从使用者目标出发，判断方案是否满足需求，例如固定管理名额能覆盖多少未来出险车辆。
- **MOP（Measure of Performance，性能指标）**：检验系统具体技术表现的量化指标，例如风险排序质量、概率误差、运行时间。
- 两者是评价指标，不是学习率、树深度等训练超参数。划分取决于系统层级；多个 MOP 可以共同支撑一个 MOE，同一指标也可直接度量某项业务效果。[NASA 定义](https://www.nasa.gov/reference/system-engineering-handbook-appendix/)

| 效能目标 | MOE 的观察方式 | 对应技术指标与证据 |
| --- | --- | --- |
| 提前识别未来出险车辆 | 在形成预测之后的标签窗检验风险区分 | ROC AUC、AP、风险分组后续出险率 |
| 有限资源优先覆盖高风险车辆 | 固定管理名额下的命中、覆盖与相对随机选择收益 | Recall@K、Precision@K、Lift@K |
| 风险概率可用于决策 | 同一概率水平对应的实际频率是否合理 | Brier、Log Loss、校准曲线 |
| 司机和管理者能理解并使用评分 | 能追溯、复算、选择处置动作和查看更新 | 扣分追溯率、复算误差、理解测试、更新与覆盖检查 |
| 部署后改善安全结果 | 经实际运营验证的暴露归一事故变化 | 干预前后事故率、暴露量和对照设计；本轮不具备此证据 |

离线排序、预警命中或评分相关性不能证明事故被减少。官方说明指出比赛数据经过筛选、调整与模糊化，因此即使本数据集上的概率校准良好，也不能直接视为真实车队中的绝对事故概率。

## 2. 计算对象与输入边界

复用[数据契约草案](../interfaces/data_contract.md)的车辆关联、`sample_id`、`as_of`、标签与版本语义；该契约本身仍待冻结。评估器未来应将 `labels`、`splits` 与 `oof_predictions` 按声明的键一对一关联。下列 `p`、`s` 为本文数学记号，不要求实现静默重命名已有列。

| 记号 | 含义 |
| --- | --- |
| `N` | 本次预先登记的评估集合大小；主比较默认同一截点下一车一行 |
| `y_i` | 后续标签窗内是否出险，取值为 0 或 1；标签认定由版本化协议确定 |
| `N+`、`N-` | 评估集合中的正、负样本数 |
| `p_i` | 正类概率，有限且位于 `[0, 1]`，越大越危险 |
| `s_i` | 排序用风险分，越大越危险；主要比较优先采用同口径的 `p_i` |
| `S_i` | 任务二安全分，越大越安全；评价风险排序时使用 `-S_i` |
| `q`、`K`、`TP_K` | 管理比例、实际入选数量、入选车辆中后续正类数量 |

评估前必须检查以下事项：

1. 目标集合、标签版本、预测截点、观察窗、预测跨度、时区与折分版本明确。特征严格早于 `as_of`；标签窗采用 `[as_of, as_of + H)`。
2. 正式对照使用相同的非空样本集合，标签限于 0/1，概率和排序分必须有限。概率缺失、重复、越界或关联失败时，不得删掉问题车辆后继续报告为完整结果。
3. `label_status=unknown` 不得直接当负类。只有预登记且经核查的标签口径才能进入主比较；`proxy_negative` 必须声明假设与敏感性检查。有效标签覆盖与全体预测输出覆盖分开报告。
4. 单一截点按车辆统计；多窗口扩展必须另记协议，明确窗口权重和聚合方式，不能把高度重叠窗口当独立车辆。所有同车窗口的分组与拟合边界保持一致。
5. 不把原始事件条数当监督样本量。真实样本量、正类比例、折外预测、图表和结果表保存于受控本地报告，不随本文公开。

## 3. 任务一指标字典

| 指标 | 地位 | 方向 | 主要回答的问题 |
| --- | --- | --- | --- |
| ROC AUC | 官方主指标及内部主比较指标 | 越高越好 | 正类能否排在负类之前 |
| AP | 核心辅助 | 越高越好 | 排序的查准与查全综合表现如何 |
| Recall@20% | 核心辅助，20% 为建议管理比例 | 越高越好 | 管理部分车辆能覆盖多少后续出险车辆 |
| Brier 分数 | 核心辅助 | 越低越好 | 概率预测误差有多大 |
| Precision@10%/20%、Lift@10%/20% | 运营解释与辅助诊断 | 越高越好 | 名单命中率及相对随机选车收益如何 |
| Recall@10%、Log Loss、校准曲线 | 辅助诊断 | 召回越高、损失越低；曲线接近对角线 | 小容量管理和概率失准情况如何 |
| 输出覆盖、失败数、耗时、内存、复现一致性 | 工程验收 | 覆盖完整、错误少、成本符合预算 | 能否稳定交付 |

### 3.1 ROC AUC

$$
\mathrm{AUC}=\frac{1}{N_+N_-}\sum_{i:y_i=1}\sum_{j:y_j=0}
\left[\mathbf{1}(s_i>s_j)+\frac{1}{2}\mathbf{1}(s_i=s_j)\right].
$$

范围为 `[0, 1]`；相同分数各计 0.5。常数排序在两类均存在时为 0.5，但 0.5 不是合格目标。AUC 不依赖二分类阈值，不能称为分类准确率。

单一类别集合的 AUC 无定义，应输出空值及原因；不能补成 0、0.5 或跳过后假装五折完整。参考实现为 `roc_auc_score(y, s)`。[官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html)

### 3.2 AP

$$
\mathrm{AP}=\sum_n (R_n-R_{n-1})P_n.
$$

其中 `P_n`、`R_n` 是不同预测阈值对应的 precision、recall。采用 `average_precision_score(y, s)` 的口径；不与梯形积分形式的 PR AUC 混用。等分样本按同一阈值处理，不按任意逐车顺序人为打散以提高 AP。[官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)

AP 受正类比例影响，跨标签窗或跨样本集合时不能只比较数值大小。正类比例可以作为无信息参考，但不是预设目标。若没有正类则记为不可评价；若全为正类，应说明不具备风险区分检验意义，不能把高 AP 当有效识别证据。

### 3.3 固定管理名额下的指标

建议先报告 `q ∈ {0.10, 0.20}`；如真实管理容量已知，则按预登记的固定 `K` 评价。对有效且预先固定的集合，取 `K = ceil(q × N)`；要求 `0 < q <= 1` 或固定整数 `1 <= K <= N`，并同时报告实际 `K` 和 `K/N`。

按风险分降序取前 `K` 台。分数相同时，采用预先固定、与标签无关的键排序，例如 `sample_id` 字典序；排序只用于复现名单，不作为模型特征。报告截止位置的等分数量，禁止按标签选取有利的等分车辆，也不在选取前对概率四舍五入。

$$
\mathrm{Recall@K}=\frac{TP_K}{N_+},\qquad
\mathrm{Precision@K}=\frac{TP_K}{K},\qquad
\mathrm{Lift@K}=\frac{TP_K/K}{N_+/N}.
$$

Recall 衡量出险覆盖，Precision 衡量名单命中，Lift 衡量相对总体出险比例的富集。Lift 为 1 表示与总体比例相同；在相同集合与 `K` 下，三者由同一个 `TP_K` 决定，不能当成三份独立的改进证据。`N+=0` 时 Recall 和 Lift 无定义。

**以下为纯合成算例，与比赛数据无关：** 构造 `N=100`、`N+=20`、`K=20`、`TP_K=8`，则 Recall 为 40%、Precision 为 40%、Lift 为 2。含义是管理 20% 的车辆，覆盖 40% 的后续正类，名单正类比例为总体的两倍。这个例子不表示真实模型成绩，更不表示事故减少一半。

固定名额与固定概率阈值是两种不同运营政策。前者保证名单数量；后者的名单数量会随概率分布变化。不能用“固定阈值”同时承诺固定 20% 管理量。

### 3.4 Brier 分数与 Log Loss

本文明确使用二分类、未额外缩放的 Brier 定义：

$$
\mathrm{Brier}=\frac{1}{N}\sum_i (p_i-y_i)^2.
$$

范围为 `[0, 1]`。参考 `brier_score_loss` 时，核对所锁定库版本的二分类缩放与正类列语义，不能混用求和于两个类别后的另一种尺度。[官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.brier_score_loss.html)

$$
\mathrm{LogLoss}=-\frac{1}{N}\sum_i[y_i\ln p_i+(1-y_i)\ln(1-p_i)].
$$

使用自然对数。计算前先拒绝越界、缺失或非有限概率；仅为数值稳定，将合法概率截断到 `[epsilon, 1-epsilon]`，例如预登记 `epsilon=1e-15`。保存原始概率，并记录截断值和实现版本；不得用截断掩盖非法输出。[官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.log_loss.html)

Brier 与 Log Loss 同时受区分度和校准影响，不能单凭损失降低宣称校准已经正确。配合校准曲线，显示每个概率箱的平均预测、实际比例与样本量；分箱方式和数量提前固定，小样本不强行细分空箱。常数概率对照只从训练部分估计，不能用验证标签比例拟合基准预测。

### 3.5 不以 Accuracy 为主要判优依据

类别不平衡时，全预测负类也可能得到较高准确率，但没有风险排序和预警价值。Accuracy、Precision、Recall、F1 若按二分类阈值报告，应注明阈值及选择政策，仅作补充；不能取代官方 AUC，也不能通过调阈值提高 AUC。

## 4. 任务二的效能与验收

官方赛题说明规定各维度由评委打 1—10 分，再加权排序。下表权重属于官方评审维度，不是把 AUC、耗时和追溯率直接相加的算法权重；本文列出的可测证据是内部验收提议，不改变官方打分方式。

| 官方维度与权重 | 内部建议证据 | 验收边界 |
| --- | --- | --- |
| 风险区分能力 35% | `AUC(y, -S)`、评分组后续出险率与样本量、固定管理量下的覆盖 | 评分形成后的标签；不能用同一期事故扣分再验证同一期相关性 |
| 可解释性 25% | 扣分追溯率、复算最大绝对误差、司机与管理者理解测试 | 只有真实使用者测试才能支持“能理解”；SHAP 不等于扣分单价 |
| 可运营性 20% | 分档与处置规则、培训映射、申诉流程、名单容量、更新时延 | 模拟演示支持功能可用性，不证明实际事故减少 |
| 完整性 20% | 全体目标覆盖、评分范围、维度和权重说明、日/周/月更新、低覆盖标记 | 无观测不能直接判安全；不得靠时间流逝让停运或掉线车辆自动满分 |

建议将以下内容作为可复核的检查项，正式接受时由团队冻结检查集合和容差：

- **追溯完整性：** 应能将每项扣分追溯到规则版本、历史窗口及受控证据；检查分母是全部应有扣分项，不能先删掉无法追溯的项。对全量已检查范围要求 100% 可追溯；抽样检查必须标明样本量，不能外推为全量通过。
- **复算一致性：** 独立复算总分与系统总分，报告最大绝对误差；整数扣分要求精确一致，浮点计算先登记容差和展示舍入规则。
- **改善一致性：** 固定暴露量、背景、数据质量及其他行为，仅减少一项已定义为危险的行为，安全分不应降低。披露检查场景和违例数，要求已检查场景无违例；有限检查不等于证明全域单调。
- **动态与缺失：** 覆盖无新增驾驶、数据缺失、新增危险行为和持续安全驾驶场景，分别说明保分、恢复和可信度规则。
- **群体诊断：** 按预登记的暴露量、能源和数据覆盖分组，展示样本量、标签与评分差异；均值相同不自动证明公平，小样本不能支撑强结论。

若以 `S = 100 × (1-p)` 作为概率转换评分，则 `AUC(y, -S) = AUC(y, p)`，前提是采用未舍入的同一批预测。它可作为区分度对照，但不是新的模型能力，也不自然提供逐项行为扣分。

## 5. 验证与统计比较

### 5.1 比较前登记

使用[实验模板](../templates/experiment.md)登记样本集合、标签与预测跨度、时间窗、特征版本、基线配置、唯一主要改动、折分、随机种子、调参预算、主辅指标、管理容量、阈值政策、资源预算和停止条件。

主比较建议采用固定车辆级分层五折；有调参时，在每个外层训练部分内做分层三折选择。多窗口时内外层均按车辆分组，不把同车重叠窗口拆开。折内样本不足以形成两类时，应调整设计并记录新版本，不能只选择有利的有效折。

填补、标准化、经验平滑、分箱、特征选择等全部在对应训练部分拟合；外层验证不参与选择。概率校准使用外层训练部分内部产生的折外预测或独立校准子集，校准器不接触外层验证标签。[校准说明](https://scikit-learn.org/stable/modules/calibration.html)、[嵌套交叉验证](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)

### 5.2 折外报告与最终证据

- 单一截点主比较中，每台车产生一次外层折外概率。报告合并折外指标以及各折指标、样本量和正负类规模。
- 合并折外概率 AUC 与各折 AUC 均值不是同一统计量，应分别命名。原始 SVM 决策值等跨折尺度可能不同，不直接混入统一概率列；可另报折内排序诊断。
- 在每个外层训练部分内部选择二分类阈值，再应用于该外层验证部分。全量折外结果反复用于选阈值或挑方案后，不能同时声称它是完全独立的最终测试证据。
- 正式最终证据优先来自官方授权且未参与任何选择的新增标签、时间段或保留集合，不引入赛题禁止的外部数据；若当前没有，应明确是开发期内部回测，并保留限制，不为制造“最终结果”继续切碎过小样本。

### 5.3 时间成熟与跨月份外推

有未来标签的跨车辆回测不等于独立的跨月份时间外推。时间外推的训练标签窗必须在验证预测时点之前完整结束，即 `as_of_train + H <= as_of_validation`；同时控制重叠窗口与同车依赖。仅将特征时间排序不足以满足条件。

当只有有限历史时，先前提出的“20 天观察窗预测后 40 天”只能作为待确认的代理回测设计；本文不将其冻结为正式协议。训练和正式推理保持相同特征窗口语义，不能把短窗计数直接换为长窗累计量。不同时间口径共享数据时属于敏感性检查，不是新的独立测试集。

### 5.4 配对差异与不确定性

主差异定义为 `delta_auc = AUC_new - AUC_baseline`。AP、Recall 等越高越好的指标按同方向报告；Brier 和 Log Loss 的差值同样定义为“新减旧”，所以负数才代表改善。

在完全相同的车辆、标签和折外预测上进行车辆级配对 bootstrap：一次抽样同时抽取该车的新旧预测；多窗口扩展以车辆为簇，抽中车辆时携带其全部窗口。建议预登记 2,000 次重采样、固定种子与 95% 百分位区间。无正类或无负类的重采样 AUC 无定义，记录有效次数和无效原因；不得静默补值，频繁无效时需修订设计。

Top-K 指标若进行 bootstrap，每次应在重采样集合上重新排序和选取固定政策对应的 K；不能只对原名单内命中数做抽样而声称得到完整选择过程的不确定性。

这些区间条件于已有折外预测，是近似比较，不能覆盖全部模型重训、调参、车队共同时间因素和方案选择变异。多个种子只反映划分敏感性，不是新的独立数据。尝试许多方案后挑最优仍有选择偏差，不能只报最好一次。

## 6. 判优与验收规则

### 6.1 先通过硬检查

以下为建议硬检查，不是实际已通过的结论：

1. 无已知时间泄漏；输出集合与预先声明的目标集合一致，覆盖率 100%，无重复键、缺失输出或非法概率。
2. 标签与预测关联正确，未把未知标签静默作为负类；基线与新模型使用同样评估集合及协议。
3. 相同版本与配置可复现。若运行栈存在非确定性，应预先登记容差并报告实际差异，不声称逐位一致。
4. 训练、特征生成、推理和端到端耗时分开报告，同时写明硬件、线程、缓存与批量；内存和时延不超过事先登记的资源预算。尚无预算时只作测量，不报告资源验收通过。

失败结果必须保留。不能通过删除失败车辆、放宽检查器或变更分母制造通过。

### 6.2 再判断是否值得替换基线

建议在查看本轮结果前填写最小有实际意义的 AUC 增益 `delta_auc_min`、核心辅助指标可接受退化量及成本预算。本文不填无依据的绝对 AUC 目标或统一增益门槛；未登记门槛的比较只能作探索性结论。

| 观察 | 允许的内部结论 |
| --- | --- |
| 硬检查失败或比较条件不一致 | 当前结果不能用于有效判优，先排查数据、实现或协议 |
| 差值方向有利，但区间跨零或只在个别划分提升 | 有提升迹象，稳定性证据不足；不等同于证明无效 |
| 主指标达到预登记的实际增益，区间支持有利方向，敏感性与辅助指标可接受，成本满足预算 | 支持继续投入或提议替换基线，保留内部回测局限并提交真实复核 |
| AUC 提高，但管理覆盖、概率质量或成本明显恶化 | 分别报告得失，按预登记取舍处理；不概括为全面更好 |
| 只有训练指标改善，或靠更多信息与不一致调参预算取得提升 | 不能据此归因于所声称的模型改进 |

区间下界大于零可作为支持性证据；若要声称“增益至少达到 `delta_auc_min`”，应另检查区间下界也达到该门槛，而不是只看点估计。该近似区间不替代独立验证。

建议分别比较“同特征换模型”与“同模型加特征”。自研方案若是在某个基础模型上加约束、分群或融合，应加入同特征、合理调参的原版模型对照。任务状态在实现者完成后为 `review`，不能代替真实复核者标为 `accepted`。

## 7. 实验记录与交付

每次真实运行在受控本地报告中保存以下内容，不向公开仓库填入真实数值。以下是待实现的记录要求，不是已存在的评估 API。

| 内容 | 必填信息 |
| --- | --- |
| 可复现身份 | 运行 ID、代码提交、工作树状态、依赖版本、硬件、线程、随机种子 |
| 数据与协议 | 数据/标签/特征/折分/指标版本、窗口与时区、目标集合、标签有效性、拟合边界；敏感指纹仅留受控目录 |
| 主辅指标 | ROC AUC、AP、Recall@20%、Brier；其他诊断、各折数值、管理政策、阈值、失败原因 |
| 配对比较 | 对照版本、差值方向、置信区间、重采样单位与次数、预登记门槛、成本和局限 |
| 工程质量 | 输出覆盖、非法值与重复数、复现差异、分阶段耗时、内存 |
| 四维状态 | 实现/契约、实验效果、验收/证据、环境/依赖分别用 pass / partial / fail / not_run / blocked 说明 |

最小图表遵循[验收规范](../ACCEPTANCE.md)：特征与标签时间轴、ROC/PR 曲线、风险分组后续比例与样本量、Top-K 覆盖、概率校准曲线、相对基线差值及区间、效果与成本比较。任务二增加扣分追溯、评分随行为变化和缺失场景演示。真实图表与绘图底表遵守[数据边界](../DATA_POLICY.md)，默认仅留受控目录。
