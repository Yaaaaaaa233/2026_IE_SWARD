## 目标与结论边界

叶安线此前将主要精力放在构建特征上，FEAT-009 已证明 F3 表可以取得较强的开发期排序，但该结果没有拆开“哪些特征族有效”和“模型是否适配得当”。本任务借鉴王健祺线独立特征组建模、先保存 OOF、再检查互补融合的迭代方式，把 FEAT-009 已形成的特征优势转化为可比较的模型版本。

这不是全项目评价器的接受或公共基线变更。EVAL-001 的全项目责任人复核仍可继续；本任务仅复用其 v1.3 技术登记里的主辅指标和配对方法作为**任务内探索口径**。标签及折分继续使用官方澄清后的 `label_v2_record_count_20260923` 与 `split_v2_record_strat5_seed42`。输入窗口仍是 20 天特征窗与 40 天代理标签窗；这轮结果不能当作官方独立测试成绩，也不替代最终提交的 61 天训练。

同一批 500 台车已多次用于方案和模型开发。即使逐车 OOF、配对 bootstrap 和固定折分全部正确，按这些 OOF 反复挑模型仍会产生选择偏差。任务报告必须同时给原始配对差异和“经过多轮选择、偏乐观”的限制，不得据此宣布跨线胜出、官方窗口提升、正式基线接受或任务二评分提升。

## 输入与前置机器门

只读输入包括 FEAT-009 v2 Y1 的 F3 模型表及 manifest、FEAT-011 S0 特征来源台账、FEAT-009 有效 Y3 F3 OOF。任务开始时将它们的 SHA-256、协议版本、行数、标签数和特征视角列名哈希写进受控 `outputs/feat-012/<run-id>/preregistration.json`；登记完成后才运行任何候选 OOF。

机器门必须验证：

- 输入哈希与 FEAT-009 manifest 一致；标签、折分逐行绑定到指定 v2 标识，样本及 gpsno 唯一，五折均含两类；历史 OOF 的样本顺序和标签逐行匹配。
- 模型列与 FEAT-011 S0 台账中 `retain_candidate` 的 F3 预测列完全一致；拒绝未来信息、标签、元数据、禁用画像字段、`_cohort_` 派生列及未知来源列。
- 每个外折只在另外四折拟合填补、编码、筛列与模型；一车只获得一次 OOF 预测；完整保存折号、训练样本指纹、输入与代码哈希。
- 公开 Git 只放代码、方案和不含真实结果的交接；真实指标、逐车预测、真实特征统计和派生图表留在被忽略的受控 `outputs/feat-012/`。

若任何输入门失败，记录失败 run 并停止真实候选运行；不得临时改列、改标签、换折分或从旧协议补值。

## 多轮实验预登记

候选预算最多 19 个版本；失败尝试也留 run 记录。固定模型随机种子为 42，每个独立模型臂在冻结五折上运行一次，全部预处理在外折训练部分拟合，禁用 cohort 衍生变换。

**第一轮：单视角与单模型适配，最多 13 版。** 所有视角只从锁定 F3 表和 S0 特征族台账派生：

| 视角 | 构造 | 要回答的问题 |
|---|---|---|
| full | 所有已登记候选特征 | EBM-A 锚复现及更强平滑、树模型能否利用宽特征 |
| slim_night | 台账中的 slim F3 列 | 细分夜间列预算是否稀释其他信息 |
| history | evt、f1、f2、f2r2、accident、历史／险情序列相关族 | 事件历史本身能否构成更稳的核心视角 |
| no_traj | full 去掉 f3_traj、traj | 轨迹族对现有整体效果的净贡献 |
| no_accident | full 去掉 accident 族 | 模型是否过度依赖基础事故严重度特征 |
| no_legacy | full 去掉 f1、f2、f2r2 | F3 扩展信息是否能脱离早期特征族工作 |
| event_signal | evt、accident、f3_hist、f3_chain、f3_event、f3_fatigue、f3_score | 事件结构与险情特征能否形成紧凑模型 |

固定候选含 full 的 EBM-A（0 交互、64 bins、leaf 10）、EBM-C（0、32、20）、更强平滑 EBM-D（0、24、30）、浅 RF、浅 HistGradientBoosting；并在 slim/history 视角比较 EBM-A/C，在 slim 视角比较 RF，在 no_traj/no_accident/no_legacy/event_signal 视角比较 EBM-A。参数不按外折得分逐折调整。EBM-A 是内部复现锚，须与 FEAT-009 原有 F3 OOF 对账；显著偏离时先定位实现差异，再解释其它臂。

**第二轮：视角互补，最多 6 个版本。** 按第一轮 pooled OOF AUC，在每个特征视角内保留分数最高的算法版本；稳定按名称打破平分，再取分数最高的四个不同视角。对这四个 OOF 预测的六个两两组合，固定使用裁剪后 logit 等权平均。成员选择和融合比较依赖第一轮 OOF，因而本轮明确属于自适应探索；不再追加权重网格。

如第一轮少于四个有效视角，则只融合现有不同视角的所有两两组合；有效版本总数仍不得超过 19。无效、异常或未完成版本不静默删除，须在总表标明原因。

## 评价与停止

主指标为合并五折的 pooled OOF AUC；相对本轮 full EBM-A 报告车辆分层配对 bootstrap 2,000 次、种子 42 的 95% 百分位区间。辅助报告 AP、Recall@100、Brier、每折 AUC、拟合耗时及实际进入预处理的列数。FEAT-009 历史 F3 OOF 只作锚复现检查，不替代本轮固定主对照。

指标方向及既有参考线使用 EVAL-001 v1.3 的任务内技术口径：区间下界大于 0 表示固定配对抽样下的正向迹象；下界达到 +0.01 才达到其实际意义参考线；辅助项查看 Recall@100 不劣于 0.02、Brier 不恶化超过 0.005。这里的区间没有校正多轮择优，不能写成经过选择后仍具统计保证。候选名次只用于下一轮探索方向；任何正式采纳仍需后续独立预登记与团队评审。

停止条件：机器输入／防泄漏校验失败即停；full EBM-A 未能解释性复现 FEAT-009 则先暂停候选解读；运行 19 个版本或环境无法提供预登记模型时收口；第一、二轮完成后不自动追分，不新开无记录版本。所有版本、失败、配置、OOF、图、表、依赖和摘要保留在唯一 run 目录，可通过忽略整个新 run 回退，不覆盖 FEAT-009/011 或王健祺线产物。

最终交接提供本地总表、OOF 配对图、特征视角效果图、参考锚复现差异、版本与失败清单、复现命令及未验证项。报告要区分“某视角有信号”“本轮最佳候选”“具有可信独立增益”三种说法；前两者可作为后续假设，第三者本任务无法证明。
