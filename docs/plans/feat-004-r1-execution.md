## 1. 目标

在冻结基线（RF@F0_v1）之上交付第一轮特征增量：以设备系→车辆系对齐为前提，按赛方《IMU 数据风险分析参考资料》提取六场景事件（高频行为信号，F0/F1 均未覆盖），产出**事件级产物表**（任务二扣分明细直接消费）与每车聚合特征；同步并入多窗口族复验与历史险情族交叉构造。按 ADR-0004 判据配对判定，过门则基线棘轮前进。

## 2. 设计输入（FEAT-003 探针结论的内化）

| 探针结论 | 设计响应 |

| 高风险簇欠预测、44/64 漏检与覆盖无关 | 六场景暴露归一特征（per_1000km/per_100h）直接刻画"里程强度×行为" |

## 3. 技术方案

### 3.1 对齐矩阵（每车 3×3 旋转 R）

- 垂直轴：窗内行驶行加速度均值方向（低频重力估计），单位化；
- 前向轴：水平面（⊥垂直轴）加速度主成分 PC1；横向轴＝两者叉积；
- 质量指标与通过判据沿用探针 D（重力范数 ∈[0.85,1.15]g、前向/横向方差比 ≥1.3、日稳定 |cos|≥0.8）；判据阈值在实现期可微调并登记；
- 产出：`f2_alignment.csv`（每车 R 九元组＋质量指标＋通过标志）。

### 3.2 六场景提取（对齐后坐标系，阈值按"分布先行校准"分能源类型设定）

**校准流程（先扫描、后定阈，2026-09-22 修订：响应参考资料"不同车型达到风险级别的信号特征可能有差异"条款）**：

1. 第一遍扫描（§3.5）在对齐统计之外**同时累计分能源类型的信号分位数表** `f2_signal_quantiles.csv`（行驶态前向/横向加速度、|gyro_z'| 的 p50/p95/p99/p99.5/p0.5 等；仅特征窗信号、无标签参与——防泄漏）；
2. 阈值设定规则（预登记）：**分位数法为主**——每类型的触发阈值取该类型信号分布的对应极端分位（如急刹＝该类型前向加速度 p0.5 附近、急加速＝p99.5 附近），使"风险事件"语义对齐到各类型自身的物理能力边界；叠加**全局物理护栏**（阈值不得低于物理合理下界，如急刹阈值不低于 0.10g，防止把类型固有特性当事件）；中低频场景（碰撞/侧翻）保留物理阈值为主（本身即极端事件，分位法样本不足）；
3. 若扫描显示各类型分布基本重合，则退回全局统一阈值并登记证据（校准结论两种走向都留痕）；
4. 触发后按类型复核事件率（每千公里），与官方碰撞预警率做类型内相对对照。

| 场景 | 核心判据（校准后分类型阈值；下列为物理护栏与结构） | 频次预期 |
| --- | --- | --- |
| 急加速 | 前向 a > 类型 p99.5（护栏 ≥+0.10g） | 高频 |
| 急刹车 | 前向 a < 类型 p0.5（护栏 ≤−0.10g） | 高频 |
| 急转弯（L 型） | \|gyro_z'\| 与 \|横向 a\| 双阈值（类型分位），**方向一致双约束**，持续 ≥2s | 中频 |
| 猛打方向（S 型） | 同上双约束但短时反向交替（<2s 反向），波动强度超正常转弯 | 中频 |
| 疑似碰撞 | 前向/侧向/复合三分（物理阈值：±0.5g 级） | 低频 |
| 疑似侧翻 | 倾斜偏离 ≥0.35g 且 \|gyro_z'\| ≥ 45 dps（物理阈值） | 极低频 |

- 防误报：同型事件冷却 30s（一次操作只计一次）；触发行要求速度 ≥10 km/h（沿用 F0 moving 语义）；
- **校准边界**：分位数表仅由特征窗信号计算；仅以官方碰撞预警族做时间对齐命中率作相对校准信号；绝不用标签窗事件或标签调参。

### 3.3 事件级产物表（任务二接口，schema 一次成型）

`f2_events.csv`：`gpsno, as_of, event_time, scenario(六场景枚举), duration_s, peak_intensity_g, peak_gyro_dps, speed_kmh, confidence(旗标派生), energy_type`。字段一旦被任务二消费即冻结（ADR-0005 §4）。

### 3.4 每车聚合特征（并入 model_input，F2_v1）

- 六场景计数与频率：`f2_<场景>_count_20d`、`_rate_10k`、`_per_1000km`、`_per_100h`（暴露归一双轨，低暴露置缺失＋指示列）；
- 复验并入：F1 多窗口族 15 列（FEAT-003 裁定）；
- prior 交叉构造：`f2_prior_incident_per_1000km`（已有归一轨复用）＋ prior 险情计数×夜间/高速暴露占比交互列（语义命名）；
- 对齐元数据：`f2_align_pass`、`f2_forward_lateral_var_ratio`；
- 顺手修复：F0 遗留的 IMU 频率特征分母为 0 置 0 问题在 F2 聚合层修正为缺失（不改 F0 产物）。

### 3.5 实现与算力

- 代码：`feature_engineering/src/accident_pipeline_f2/`（沿用 f1 模块化模式）＋`configs/pipeline_f2_v1.example.yaml`＋合成数据测试（含窗口边界与标签窗排除断言）；
- 两遍流式扫描（避免 88M 窗行进内存）：第一遍累计每车对齐统计量**与分能源类型信号分位数**（校准输入），第二遍按校准后阈值应用 R＋触发＋聚合；分块多进程沿用 F0 设计；
- 本地配置 `*.local.yaml` 不入库；F2 产物落仓库外独立新目录（冻结目录只读）。

## 4. 评估与消融（步骤同 FEAT-003，统一评估器）

1. 候选＝冻结 RF 规格 @ F2_v1，对基线 RF@F0_v1 配对 bootstrap（PREREG）＋多种子旁证；
2. 消融：F2 全量／仅六场景族／六场景+对齐元数据（不含多窗口）／F0+多窗口（复验 FEAT-003 结论）／对齐救回贡献（方向特征在方向异常车子集上的对照）；
3. 过门则按 ADR-0004/0005 棘轮前进并群内知会双线；未过门按负结果登记。

## 5. 验收（对照规程矩阵迭代轮次行）

- L1：全项＋版本三件套＋`f2_events.csv` 契约校验（主键唯一、时刻在特征窗内）＋合成测试；
- L2（轻量口径）：对齐规程抽样（含方向异常车目检窗段）＋六场景抽 10 个事件人工对原始窗段＋与官方碰撞预警时间邻近交叉核对（相对校准信号）；若被采纳为基线则补全完整 L2；
- L3：图组 B（新特征分布与单调性）＋C（对齐前后三分量与异常车对比）＋D（事件交叉散点）；采纳时补 E。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 高频场景事件率过低或过饱和 | 阈值初值保守＋事件率分布检查，冷却与速度门槛防重复计数 |
| 对齐失败车特征缺失引入偏差 | align_fail 标志入模＋消融对照；失败车保留方向无关特征 |
| 88M 行两遍扫描算力 | 探针实测单遍约 4 分钟，两遍＋触发计算预算 30-60 分钟，必要时分夜跑 |
| 六场景无增益（负结果） | 消融定位（阈值不合适 vs 信号本身弱）；阈值不靠标签窗调整，改用碰撞预警相对校准 |
