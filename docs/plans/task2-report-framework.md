# 任务二报告框架与双人分工

版本：v0.1
状态：报告结构草案
适用基线：`task2-final-rules-v1` 与 `final-v1-dyn-policy-v1`
人员：周航正、娄澜

版本前提：任务二冻结规则当前记录的教师是 `sprint-g10-final`，但 [ADR-0011](../decisions/ADR-0011-task1-g8-final-freeze.md) 已把任务一正式算法冻结为 `g8v6-corrected`。最终报告开始填真实结果前，组长必须先裁定：保留 g10 作为任务二内部教师并明确与任务一终版不同，或基于 g8v6 新开规则版本、完整重跑后训练和动态层并重新走 R4。不能只替换教师名称而沿用旧分数和指标。

## 1 报告的主线

报告围绕一个完整闭环展开：先把驾驶事件归入稳定的人因维度，再用“零标签规则预训练＋教师定向后训练”形成可解释扣分规则，随后用未来事故与未遂验证风险区分度，最后把静态分数转成排名、干预、改善和表扬机制。

这里的“预训练”和“后训练”是规则参数的分阶段学习，不是神经网络迁移学习：

1. 预训练阶段使用行为频率和组内结构建立透明规则骨架，不读取结果标签；
2. 后训练阶段使用任务一折外概率提供严重度方向，对规则进行有限锐化；
3. 真实未来事故与未遂只承担效果验证，不与教师一致性混在同一结论中；
4. 动态层在冻结规则上做滚动重放和运营状态更新，不静默修改基础规则参数。

建议报告标题暂定为：

> 基于多源驾驶行为证据的可解释安全评分与运营管理体系

## 2 两个人的工作划分

### 2.1 分工原则

两个人按“方法规则层”和“结果运营层”拆分。规则层负责分数怎样算、为何这样算；结果运营层负责分数是否有效、怎样展示、怎样转成管理动作。这样可以避免两个人同时修改冻结规则，也能让报告中的方法和应用相互校验。

| 模块 | 娄澜负责 方法规则层 | 周航正负责 结果运营层 | 交接接口 |
| --- | --- | --- | --- |
| 分类体系 | 说明22类事件、5个公开维度、内部语义组和去重边界 | 检查分类能否对应运营动作和可视化标签 | 分类合同版本与维度名称 |
| 扣分规则 | 写清V3规则预训练、组内融合、发布收缩、S2后训练锐化 | 检查输出字段、分数方向、证据状态和可复算性 | `rule_config.json` 与规则说明 |
| 动态应用 | 负责滚动重放、滞回门、动态政策参数和技术边界 | 把动态状态转换为关注、改善、解除和表扬名单 | 动态分、状态变化、入区与出区标记 |
| 预测结果 | 提供规则版本和必要的技术解释 | 负责统一评价、对照表、分群表现、稳定性和案例分析 | 固定折分、未来标签、R4结果表 |
| 可视化 | 提供行为扣分、维度分和动态状态的计算口径 | 负责雷达图、排名、趋势、瀑布图和UI信息架构 | 统一展示数据集 |
| 运营建议 | 说明哪些参数允许运营配置、哪些属于冻结规则 | 负责干预策略、优秀表扬、申诉复核和管理节奏 | 风险等级、原因、置信度、变化趋势 |
| 报告整合 | 主写第3至第5章的方法内容 | 主写摘要、第6至第10章并负责总稿合并 | 章节清单与图表编号 |

### 2.2 文件边界

- 娄澜继续维护 `task2/final_rules_v1_dyn/` 及其方法说明，不在报告工作中改动已冻结参数。

### 第7章 可视化与交互界面

可视化遵循三条原则：同一方向、显示证据、能触发动作。安全分和维度分均为越高越好；风险指标单独标注为越高越危险。

#### 7.1 六维雷达图

推荐六个轴为：

1. 清醒与疲劳管理；
2. 注意力管理；
3. 操控稳定性；
4. 安全空间管理；
5. 规则与安全配合；
6. 证据可信度。

第五类行为能力与第六轴证据可信度不是同一种概念，界面必须用不同颜色或虚线区分，并写清“可信度低表示判断依据不足，不等于驾驶更危险”。总安全分放在雷达图中心，不把总分重复作为第六轴。近期改善趋势用时间曲线表达，不塞进雷达图。

#### 7.2 积分排名

排名至少同时显示总分、风险等级、较上期变化、证据可信度和有效暴露。只在满足最低暴露的可比车辆之间形成正式名次；低暴露车辆进入“待观察”，不与正常暴露车辆争夺优秀名额。

#### 7.3 四类运营名单

| 名单 | 进入条件 | 主要用途 |
| --- | --- | --- |
| 重点关注 | 低分且证据充分，或进入双预警区 | 安全培训、复盘和主管跟进 |
| 观察提醒 | 中风险、低证据或短期恶化 | 补采数据、轻提醒和复核 |
| 改善进步 | 分数持续提高并解除关注状态 | 正向反馈、巩固改善行为 |
| 优秀表扬 | 高分、证据充分、连续稳定且无结果门触发 | 月度表扬、经验分享和正向激励 |

优秀表扬不能只按单次高分决定，建议同时要求：最低有效暴露、证据可信度达标、连续多个周期稳定、无待核查异常。表扬规则与处罚规则同样公开，避免只强调扣分。

#### 7.4 页面结构

1. **车队总览页**：总体均分、风险分布、重点关注数、改善人数、优秀人数；
2. **积分排名页**：可筛选车型、能源类型、组织和证据状态；
3. **司机详情页**：总分、六维雷达、扣分瀑布、60日趋势、前三原因和建议；
4. **运营工作台**：关注名单、处理状态、负责人、截止时间和复核结果；
5. **规则说明页**：规则版本、档位、数据覆盖和申诉复核入口。

责任人：周航正主设计和出图，娄澜复核计算口径。

### 第8章 运营建议与管理闭环

本章把评分转成“谁在什么时间做什么”的动作，不只给泛化建议。

#### 8.1 分层干预

- 高风险且证据充分：24小时内复盘，针对前三原因制定训练；
- 中风险或近期恶化：周度提醒，观察下一周期是否持续；
- 低证据：优先排查设备、里程和数据覆盖，不直接处罚；
- 改善车辆：解除部分关注并反馈具体改善项；
- 稳定优秀车辆：进入月度表扬和经验分享候选。

#### 8.2 按维度给行动

| 维度 | 司机建议 | 管理者动作 |
| --- | --- | --- |
| 清醒与疲劳 | 合理休息、避免连续驾驶、疲劳信号后及时停车 | 调整班次、复核夜间任务、安排疲劳教育 |
| 注意力 | 减少电话和低头操作，驾驶前完成设备设置 | 推送具体事件复盘，检查座舱设备交互 |
| 操控稳定 | 平稳保持车道，提前规划变道 | 结合道路和车辆条件复核，安排操控训练 |
| 安全空间 | 增大跟车距离，降低高风险场景速度 | 检查高频路线，安排防御性驾驶培训 |
| 规则与配合 | 遵守分场景限速，保持设备正常可用 | 复核道路限速、设备状态和异常申诉 |

#### 8.3 闭环和申诉

评分发布后依次经历：提醒或表扬、原因确认、行动登记、下一周期复评、解除或升级。设备异常、错误匹配和特殊任务允许挂起复核；挂起期间不把未核实证据转成正式处罚。

责任人：周航正。
