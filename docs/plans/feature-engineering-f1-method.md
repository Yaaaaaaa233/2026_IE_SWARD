# F1_v1 特征升级方法与边界

状态：实现者自测，待团队复核
对应任务：[FEAT-002](../tasks/FEAT-002.json)
代码入口：[feature_engineering](../../feature_engineering/README.md)

本文只记录可公开的方法和接口边界，不包含比赛数据统计、车辆明细、真实模型结果或聚类产物。F1_v1 与 F0 并存，不静默改变冻结折分或标签定义。

## 1. 设计原则

1. 所有特征只读取 `[as_of-L, as_of)`，`as_of` 当天及标签窗口事件不得进入特征。
2. 原始计数和暴露归一率并存；低暴露不制造大数，也不把缺失解释为零风险。
3. 无历史事件的时间间隔保留缺失，并配套 `never_*` 指示列。
4. 标签、折号、标签窗口和版本字段是元数据，不进入模型特征。
5. 监督特征筛选只能在训练折内完成；公开特征映射不依赖全量标签指标。
6. 数据、真实特征、预测、模型和报告按 [DATA_POLICY](../DATA_POLICY.md) 留在受控目录。

## 2. F0 工程底座

F0 提供以下通用能力：

- Arrow 分块读取 IMU 分片，并用可合并统计量控制内存。
- 使用三轴加速度模长构造方向不变的冲击强度。
- 对依赖安装轴向的特征增加可靠性门控。
- 生成冲击、旋转、倾斜、碰撞候选、翻滚候选及质量特征。
- 将事件、轨迹、车辆属性、覆盖质量、IMU、标签和折号统一到 `sample_id`。
- 校验主键唯一性、样本集合一致性和禁止字段隔离。
- 对无有效观测样本标记 `insufficient_data`，不让缺数据主导行为聚类。

IMU阈值是工程候选值，不代表已通过事故回放校准。代码可运行不等于该特征组已经证明有预测增益。

## 3. F1 历史险情特征

F1_v1 从官方事故和未遂事件类型构造：

- 历史事故次数。
- 历史未遂次数。
- 历史险情合计。
- 从未发生事故／险情的指示列。
- 距离最近事故／险情的天数。

时间间隔无事件时保持缺失，不能填0。事故与未遂分列并保留合计，让下游模型在训练折内学习权重。

## 4. 暴露归一双轨

对事件计数和选定IMU计数同时保留：

- 原始计数。
- 每千公里发生率。
- 每百小时发生率。
- IMU每万条记录率及每千公里率。

当里程或时长低于配置门槛时，归一率置为缺失，并输出低暴露指示列。门槛写在共享配置模板，实际取值在实验冻结前仍需复核。

## 5. 多尺度窗口与新近度

事件族使用5天、10天和20天窗口。近期抬升采用带平滑的比值：

```text
(count_5d + 0.5) / (count_20d / 4 + 0.5)
```

事件族按官方类型的业务含义映射为车道、疲劳、分心、超速和碰撞预警；设备异常单独作为质量特征。映射本身不读取标签。

F1_v1 不机械复制全部静态和IMU特征到三个窗口。静态属性没有窗口语义；IMU多窗口应在阈值稳定性得到验证后另行评估，避免未经验证的信号成倍扩张。

## 6. IMU回放校准门槛

代码使用 `min_gold_accidents_for_imu_calibration` 配置最小金标准事故数量。预测时点前、时间戳经过核验的事故少于门槛时，只输出 `deferred_insufficient_gold_accidents`，不修改阈值。

标签窗口事故不能用于当前样本的阈值选择。即使金标准数量满足门槛，阈值敏感性扫描仍须在训练折内或独立校准集上完成。

## 7. 不采用的高风险做法

- 不按全量样本单特征AUC预选事件类型后再复用同一折评估。
- 不在严重度、持续时间或置信度字段缺失时人工编造加权系数。
- 不把全局插补统计量提前写入模型输入；中位数等学习步骤必须在训练折内拟合。
- 不把探索性聚类阳性率作为正式模型成绩。

## 8. 输出契约

受控本地运行输出：

- F1事件候选特征及校准可行性记录。
- `model_input.csv` 与 `feature_schema.json`。
- F1逐列字段字典。
- 聚类模型、分派和画像。

这些产物不进入公开Git。公开仓库只保存源码、配置模板、合成测试和本方法说明。

## 9. 验收顺序

1. 安装模块依赖并运行合成测试。
2. 核对 `sample_id`、时间窗口、禁止字段和缺失语义。
3. 在冻结折分上依次验证历史险情、暴露归一、多窗口和事件语义特征。
4. 使用配对折外结果报告增益与不确定性，不只报告最好一次。
5. 只有稳定支持的特征组才能进入冻结版本；否则标为暂缓。
