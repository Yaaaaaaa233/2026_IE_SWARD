# FEAT-009 叶安线：已有特征的建模优化方案

状态：**ready／叶安于 2026-09-23 确认方案并授权入库；S0–S3 均未运行**。版本 v1.0，2026-09-23。本文件成为 FEAT-009 的执行基线；实施代码、真实数据实验和后续验收需另按每步放行条件推进。

任务：[FEAT-009](../tasks/FEAT-009.json)。上位方案：[任务一双线优化方案](task1-optimization-plan-v1.md)阶段 1；评估与验收遵循 [ADR-0004](../decisions/ADR-0004-baseline-freeze.md)、[ADR-0005](../decisions/ADR-0005-task1-dual-track-and-task2-split.md)、[任务一验收规程](task1-optimization-acceptance-v1.md)及 [roadmap 编写要求](roadmap_requirements.md)。本文件把“r5 后不再做特征提取迭代”和“继续优化现有特征的学习算法”分开：不登记 r6，不改变冻结评估器、标签、折分或上游特征语义。

## 1. 问题、假设和证据边界

现有 F3R5_v1 主要按冻结 RF 判定；既有汇合诊断将新特征交给**在 F1 上选定成员的固定 V5**，未针对 F3 重新选择学习器与复杂度。前述实验只支持“这些直接组合未过门”，不能证明现有特征经模型适配后没有价值。历史消融和汇合诊断已看过标签，仅用于提出假设，不作为本任务的独立采纳证据。

- **H1（唯一主要效果假设）**：在 F3R5_v1 上，按预先锁定的小候选池于各外层训练折内选择学习器，可形成相对当前最强登记方案 V5 有正向增益的车辆级折外排序。
- **H2（次要机制假设）**：同一选择程序在 F3R5_v1 与 F1_v1 上的差异，可识别新增特征是否需要不同模型形态；两模型排错车辆可能互补。
- **局限**：五折 OOF 仍是开发期同一批车辆；既有多轮实验使最终赢家有选择偏差。即使 H1 过门，也只按 ADR-0004 登记为内部候选，不称独立测试成绩或通用性能上界。

## 2. 冻结输入、候选池和裁决口径

| 项 | 拟定口径 |
| --- | --- |
| 输入 | F1_v1 与 F3R5_v1 已有 `model_input.csv`；按 `sample_id` 对齐，核对 `gpsno`、`y`、`fold` 逐车一致，记录实际文件指纹；不重扫原始 IMU／轨迹。F3 manifest 如有未填指纹，另对实际输入计算指纹，不把占位符当已验收。 |
| 特征 | 除 `y`、`fold`、车辆标识、时间／版本字段外的数值与类别特征；缺失填补、类别编码、任何有数据拟合步骤只在训练折内进行。审计 F3 既有全量近常数／相关性筛列；若其结果影响严格归纳评估，须把筛列移入训练折或将结论标为转导式开发诊断，不能隐去限制。 |
| 折分 | 固定车辆五折不变；每个外层训练集内再分层三折选模型；主种子 42，7／2026 只作稳定性旁证。 |
| 候选池 | EBM-A：`interactions=0`；EBM-B：`interactions=5`；二者固定 `max_bins=64`、`min_samples_leaf=10`。LightGBM-A：`num_leaves=4`、`min_data_in_leaf=30`；LightGBM-B：`num_leaves=8`、`min_data_in_leaf=40`；二者固定 `learning_rate=0.05`、`n_estimators=200`、`reg_lambda=1`、`feature_fraction=0.8`、无单调约束。实现前核实与本机安装版本相容；改变候选池须先修订本方案，再运行主判定。 |
| 选择 | 每个外层训练集仅用其内三折平均 AUC 从四候选中选一个；分数完全相同时按上表顺序选复杂度更低者；再用该外层训练集拟合，预测留出折。F1 与 F3 分别运行相同程序，不用外层标签选参数或筛列。 |
| 对照 | 主比较：F3 选择程序 vs 当前最强登记 V5 的同车 OOF；同时报告 vs ADR-0004 原 RF 锚点。次比较：F3 与 F1 同选择程序。V5 在正式裁决前应核实输入／OOF 指纹和 `review` 验收状态；若 V6 已正式采纳，则补报对新的当前基线。 |
| 判据 | 仅一次预登记主判定：车辆级配对 bootstrap 2,000 次／95%／seed42，点估计 ΔAUC>0 且区间下界>0，Recall@100 与 Brier 退化不超过 ADR-0004 容忍度。区间下界 ≥0.01 才称“有实际意义增益”；多种子不得代替主判定。 |

本候选池已随方案确认，**尚无执行结果**。若 EBM 或 LightGBM 环境缺失，不擅自删候选后称同一预登记实验通过；记录阻塞并在运行前修订方案。已有 MODEL-004 的单调 LightGBM 负结果不等于本方案无约束 LightGBM 的结果。

## 3. 执行步骤与三层验收

以下命令是**实施后必须提供的入口目标**，当前尚未实现，不表示现在可运行。每一步的方案、机器验收和人工图表规则须先经负责人人工核查并入 Git，再执行该步；真实结果只进受控 `outputs/feat-009/`。

### FEAT-009-S0 输入锁定与无泄漏审计（状态：not_run）

- **目的／依赖**：在 FEAT-008 产物与 MODEL-005 V5 OOF 可取得后，确定同车可比性、输入版本和折内拟合边界；负责人叶安。
- **具体操作**：只读装载 F1、F3、V5 OOF、原 RF OOF；逐车对账主键、标签、折号、时间窗和版本；生成输入指纹与特征族清单；审计 F3 筛列、同群变换及 V5 分群材料的拟合范围。产出受控 `outputs/feat-009/s0/manifest.json`、`audit.json` 和问题清单。
- **机器验收**：拟实现 `python feature_engineering/experiments/task1_feature_modeling/audit.py --config <local-config>`；重复键、样本／标签／折号不一致、缺失指纹、元数据入特征、未来窗口列须非零退出。至少用一份人为改错的合成输入证明检查会拒绝。指纹复算一致；不公开真实指纹或逐车值。
- **人工可视化验收**：一页输入流向与时间窗图、F1／F3 特征族及缺失情况图、折内／折外拟合边界表；每图标版本、样本量、时间范围与一句解释。复核人对照 manifest 与上游字段字典抽查。
- **放行**：叶安人工确认审计没有未解释的标签泄漏或口径漂移，任务记录写入审计结论，才可进入 S1；问题未闭合时标 `blocked`。

### FEAT-009-S1 四候选折内选择与一次主判定（状态：not_run）

- **目的／依赖**：检验 H1，同时用同一选择程序回答 F1／F3 的模型适配差异；依赖 S0 通过。
- **具体操作**：实现可复跑训练入口；在每个固定外层折分别对 F1／F3 执行上表四候选的内三折选择，输出两组完整 OOF、每折选型与训练配置。冻结代码、配置和输入指纹后，只做一次 F3 vs V5 的主判定；F1 对照与四候选内折分数仅作机制诊断，不从中事后挑一个冒充预登记主候选。
- **机器验收**：拟实现 `python feature_engineering/experiments/task1_feature_modeling/run.py --config <local-config>` 与 `python feature_engineering/experiments/task1_feature_modeling/check.py --run-dir <controlled-run>`；断言每车仅一个外层预测、训练索引与验证索引不交、填补／编码／选型均只见外层训练车、预测有限且在 `[0,1]`、输入指纹与 S0 相同；故意把验证标签送入选型的合成测试必须失败。配对脚本给出点估计、区间、辅助容差和采纳判定；固定配置重复运行预测一致。运行中断保留失败记录，不按有利折挑结果。
- **人工可视化验收**：同车相对 V5／原 RF 的 ΔAUC 区间图（零线、样本量、判据线）、逐折表现与选中候选表、成本与效果图；图表与结果 JSON 来自同一 run ID。复核人逐项核对“主判定”与“次级诊断”标识。
- **放行**：主判定结果无论正负都登记。若过门，补全 L2/L3 后才可建议采纳；若未过门，不自动进入无限调参，而由人工看 S2 的诊断价值。

### FEAT-009-S2 特征族和互补性诊断（状态：not_run；不作采纳判定）

- **目的／依赖**：解释 S1 是否受某类特征或车型／覆盖场景驱动，判断值得另立一次预登记融合任务与否；依赖 S1 结果完整。
- **具体操作**：在受控目录对 S1 的 F1／F3／V5 同车 OOF 做排名散点、前 K 名单交并、两模型互相排对／排错的车辆分类，以及各外层折模型选择的稳定性。轨迹／质量／综合分的归因只作为解释素材；本任务尚无特征族自动选择程序。可提出下一任务候选，但不对这些诊断变体重新宣告本任务过门。
- **机器验收**：拟实现 `python feature_engineering/experiments/task1_feature_modeling/diagnose.py --run-dir <controlled-run>`；断言全部比较使用同一车辆集合、同一标签／折号、未舍入的排序分；图的底表与 OOF 指纹一致；缺任一输入非零退出。
- **人工可视化验收**：V5×本线模型风险排名散点、前 K 重叠图、误差互补矩阵、每折所选模型图；小群标人数与正类数，禁止把个别车故事写成整体收益。
- **放行**：叶安与王健祺只裁定是否值得另开融合／特征族选择任务；如要试新组合，先单独预登记候选与预算。当前同一批 OOF 上的重复选择必须在报告中标为开发期诊断。

### FEAT-009-S3 复核与交接（状态：not_run）

- **目的／依赖**：让模型线、任务二和阶段 3 人工推进门能引用真实、边界清楚的结果；依赖 S1，必要时 S2。
- **具体操作**：形成受控一页验收报告、OOF／配置／代码／输入指纹清单、公开无数值的 worklog 和任务结论。拟采纳版本补齐 L2 人工核验与 L3 图组；输出接口若供任务二消费，只增列不改已冻结 schema。EVAL-003 仍须叶安与王健祺共同宣告，代理不自行启动。
- **机器验收**：`python tools/check_governance.py`、`python -m unittest discover -s tests -v`、相关合成测试及 `--scope index` 均通过；受控报告能从同一 run ID 复算，机器检查失败非零退出。

- **放行**：主候选过当前有效基线且辅助容差通过，可提交人工终评；未过门但有明确互补性，只提出新任务；均无增益则本线停止，保留负结果与任务二特征接口。

## 4. 预算、写入域与停止条件

- **预算提案**：S0 半个工作日；S1 先跑一个外层折估算耗时，再安排至多两个工作日的完整矩阵；S2／S3 共约一天。若单折成本使本预算不可行，运行主判定前缩减候选池并修订方案，不在运行后选择有利方案。
- **写入域**：实施代码限 `feature_engineering/experiments/task1_feature_modeling/`；受控结果限 `outputs/feat-009/`；`models/`、冻结评估器、折分和王健祺线产物只读。需变更公共口径时按 ADR 协调，不在本任务私改。
- **停止条件**：输入审计未通过即停；主判定不过且无明确互补诊断即停；预算耗尽仍无可复算结果则登记 `partial/blocked`，不把探索值升格为成绩。多次尝试不得删失败记录；新模型族或融合权重搜索须新任务和新的预登记。
- **数据边界**：方案、代码、合成测试可入公开仓库；真实数字、逐车预测、真实图表、输入指纹及绝对机器路径只留受控目录。公开任务与 worklog 只写结论身份、运行编号和限制。
