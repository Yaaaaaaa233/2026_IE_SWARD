# 2026 清华 IE 亮剑《驾驶安全》整体路线图

> 团队讨论稿。核心原则：**先立评估标准（harness），再做特征与模型**——本地评估不可信，后面所有迭代都是盲跑。

## 总体打法

```
M0 数据地基 → M1 评估 harness → M2 特征工程 → M3 模型迭代 → M4 任务二评分模型
                    ↑                                    |
                    └────── 所有实验统一经 harness 评估 ←─┘
```

- 评估 harness 先行：任务一的真实标签（未来 40 天事故）在组委会手里，本地只能靠时间切分自造标签做近似评估，这套框架必须最先建好并校准可信。
- 特征"由便宜到贵"：官方事件聚合（信号强、成本低）→ 车辆画像 → 轨迹衍生 → IMU 挖掘（成本最高）。
- 任务二并行推进，不留在最后：其 35% 权重（风险区分能力）可直接复用任务一的特征体系本地度量，其余 65% 比文档质量，需要时间打磨。
- 提交物从第一周起保持可一键生成：预测 CSV、评分 CSV、说明文档、可复现代码。

## M0 · 数据地基

**输入数据现状**（官方字段定义见 `赛题资料/` 下两份 PDF）：

| 数据 | 文件形态 | 读取要点 |
| --- | --- | --- |
| 风险事件 | `事件明细.txt`（`2.风险事件明细.zip` 解压后） | Tab 分隔、无表头，7 列：`gpsno, lat, lng, event_type, event_name, speed, start_time` |
| 车辆画像 | `1.车辆画像数据.xlsx` | 直接读，约 500 行 |
| IMU | `3.IMU数据（6-7月）/part-*.gz`，30 个分片 | gzip 压缩文本，无表头，12 列（gpsno, imei, data_time, data_date, ems_speed, gps_speed, accel_x/y/z_raw, gyro_x/y/z_raw） |
| 轨迹 | `4.轨迹数据集（6-7月）/part-*`，30 个分片，无扩展名 | 纯文本 TSV，无表头，8 列（gpsno, distance, run_time, trigger_time, speed, course, lat, lng），GCJ02 坐标系 |

说明：`part-XXXXX-<uuid>-c000` + `_SUCCESS` 是 Spark/Hadoop 输出格式，`_SUCCESS` 为空标记文件，30 个分片需全部合并才是完整数据集。

**要做的事**：
1. 统一读取器：分片合并 + 按官方字段表补列名 + 类型解析（时间字符串 → datetime）。
2. 数据质检：各表车辆覆盖范围（尤其 IMU 只有部分车辆）、时间覆盖、异常值分布。
3. 清洗后按数据源分别落 parquet（`data/processed/`，不入库），之后所有实验不再碰原始文件。

**已知问题**：
- 轨迹数据集 `part-00026/27/28` 仍在下载中（`.baiduyun.p.downloading` 残缺文件），做轨迹特征前必须补齐；
- IMU 设备放置姿态不固定，需做设备坐标系 → 车辆坐标系对齐（用重力方向 + 行驶方向），见 IMU 参考资料；
- IMU 有噪音与个别不可用时段；EMS 速度个别车辆有异常信号，GPS 速度有延迟。

## M1 · 评估 harness（核心，优先级最高）

**标签构造（复刻真实任务结构）**：
- 特征窗：`2026-06-01 ~ 06-20`（20 天）→ 标签窗：`2026-06-21 ~ 07-30`（40 天），20 + 40 = 60 天严丝合缝；
- 标签定义：标签窗内该车是否出现事件编码 **11803（事故）/ 11804（未遂事故）**，出现即正类。

**交叉验证**：
- 车辆级分层 K 折（K=5，按标签分层），每台车一个样本、共 500 个样本，按车分折防止同车信息跨折泄漏；
- 多种子重复，报告 **AUC 均值 ± 波动**；正样本预计仅几十个，单次 AUC 有 ±0.05 量级噪声，任何结论必须多折多种子一致才可信。

**第二读数（对冲口径风险）**：赛题概述写"30 天"、任务详情写"40 天"，口径矛盾。另建"特征窗 6-1~6-30 / 标签窗 7-1~7-30"的 30 天版本同步评估，两个口径下结论一致的方法才算稳健；同时尽早向组委会确认。

**防泄漏红线**：
- 特征只能来自特征窗内的数据；
- 事件表中特征期出现的 11803/11804 可作为"历史事故"特征（赛题 3.1.3 明确允许），标签期的 11803/11804 只用于生成标签；
- 严禁把全 60 天事件聚合成特征（等于把答案喂给模型，本地分数虚高且不可信）。

**产出**：一个统一入口（如 `train_eval.py`），输入特征矩阵，输出 AUC 报告。此后所有实验都是"改特征 → 跑 harness → 看数字"。

## M2 · 特征工程

按成本递增分四组建模，**分组单独评估增量价值**（harness 上做消融）：

1. **官方事件聚合**（第一批就做）：25 种事件类型按车按窗统计次数与频率，**按里程或行驶时长归一**（如每千公里次数），防止"跑得多"被误判为"危险"；含特征期历史事故次数、风险事件总强度。摄像头遮挡/角度异常（41006/41021）单列"管理配合度"。
2. **车辆画像**：能源类型、月均里程/时长、停留次数、高速/早晨/黄昏/夜间占比，直接拼接。
3. **轨迹衍生**：速度分布（均值/分位数/超速时长占比）、昼夜行驶结构、里程节奏、停留模式。
4. **IMU 挖掘**（成本最高，放最后）：坐标系对齐 → 去噪 → 分车型（电动/柴油）阈值 → 急加速/急刹车/急转弯/猛打方向/疑似碰撞/疑似侧翻事件，同样按暴露量归一成频率特征；另建"有无 IMU"指示位，缺失车辆单独处理（不与有 IMU 车辆混填 0）。

**交叉验证技巧**：自挖的 IMU 急刹/疑似碰撞可与官方 30000（前碰撞预警）、30005（车距过近）做时间对齐，用命中率校准阈值（弱标签验证）。

## M3 · 模型迭代

- **Baseline 先行**：逻辑回归 / LightGBM + 第一批事件特征，先拿到基准 AUC；
- **小样本纪律**：500 样本、几十个正样本——简单模型 + 少量强特征 + 轻量集成，几乎必然优于复杂模型；特征数量克制，防过拟合；
- **受控实验**：一次只加一组特征，跑 harness 看多折多种子是否稳定提升；不追单次高分；
- **概率输出**：直接用 `predict_proba`，AUC 只看排序，无需概率校准；类别不平衡下多数车概率挤在低区间属正常；
- 可选增强：滚动窗口扩充训练样本（注意同车多窗口只能出现在同一折）。

## M4 · 任务二 · 司机安全评价模型

评分维度直接复用赛题 3.1.3 的六类：驾驶员状态 / 驾驶平稳性 / 超高危事件 / 管理配合度 / 环境道路 / IMU 行为。

- **框架**：扣分制（每类事件按危险程度设扣分单价 × 每千公里频次），基础分 100 封顶 0，司机一眼能看懂"分数怎么丢的"——满足可解释性（25%）；
- **权重**：由数据（任务一中该维度的回归系数 / 证据权重）+ 业务逻辑共同确定，写明依据——满足完整性（20%）；
- **可运营**（20%）：输出排名、分档（红黄绿）、对应管理动作（培训/奖惩）建议；
- **动态性**：日/周/月评分 = 换窗口重算同一套公式；
- **本地度量**：评分与标签窗事故的相关性 / AUC，对应"风险区分能力"（35% 权重），直接用任务一 harness 评估；
- 报告文档占得分 65%，中期就开始起草，不要等任务一收敛。
