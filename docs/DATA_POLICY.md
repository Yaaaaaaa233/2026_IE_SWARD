# 公开仓库与比赛数据边界

本项目 GitHub 当前为公开仓库。比赛要求数据仅限比赛用途并禁止泄露。原始数据之外的派生内容也可能泄露信息；聚合、匿名化或去掉车辆 ID 不自动取得公开资格。

## 默认存储规则

| 内容 | 保存位置／规则 |
| --- | --- |
| 源代码（含数据清洗／特征／评估等处理数据的脚本）、治理文档、无真实值的配置、合成测试 | 可进 Git，仍需检查内容 |
| 原始事件、画像、IMU、轨迹、数据清单和数据指纹 | 本地 `data/` 或受控外部目录，不进公开仓库 |
| 特征、标签、折外预测、模型、提交 CSV | 本地 `artifacts/`、`outputs/` 或受控目录 |
| 真实数据图表、交互报告、统计摘要、日志 | 本地 `reports/local/` 或受控目录；不得默认上传 Pages、附件、Issue 或 PR |
| 证据元信息 | 公开索引可记证据编号、代码版本、检查类型和限制；数据内容及敏感数值仍不公开 |
| 路径、密码、token、SSH 私钥 | 本地配置或系统凭据，不进 Git，不展示凭据内容 |

公开可视化样例只使用明确标注的合成数据，不能冒充实验结果。真实图表由授权成员在本机打开，或通过组委会允许的受控方式共享；不把公开站点作为默认验收平台。

硬盘与受控渠道的数据交付（交付包命名、各线目录结构、完整性清单与脚本快照、接收对数回执）遵循 [DATA_DELIVERY.md](DATA_DELIVERY.md)；处理数据的脚本属代码，脱敏复核后入 Git，不在"本地维护"状态长期滞留。

## 本地路径与可移植性

本地配置参照 [模板](../configs/local.example.toml)。代码不得硬编码成员的用户名、磁盘盘符或桌面路径。跨设备复现时记录相同的数据版本、配置、代码提交、依赖版本和随机种子；数据指纹在受控证据包中核对。

## 仓库检查的边界

- `.gitignore` 只影响未跟踪文件，不会删除已经提交的内容，也不能阻止 `git add -f`。
- 治理检查器检查实际候选文件、禁入路径、数据／模型／图像类型和部分凭据标记，但不是完整敏感信息扫描器；文本、Notebook 和 JSON 仍需要人工检查。
- 新增二进制或可疑产物默认不通过。确需公开时，先确认公开依据，再由复核人审阅检查器的明确例外；不得为方便上传关闭整类检查。
- 仓库已有的三份官方 PDF 以固定文件哈希作为既有资产登记，变更或新增 PDF 需重新审查。登记只记录它们早已入库，不声称本次确认了公开授权。
- 发现已泄露内容时先记录范围并通知负责人，由其决定删除、历史清理或权限调整；不擅自重写历史或变更仓库可见性。

本地 `docs/roadmap_validation_driven.md` 含此前数据核查统计，保持本地且被忽略；其通用路线提议以不含数据统计的 [路线入口](plans/README.md) 跨设备共享。
