# 硬盘与受控渠道数据交付规范

版本：v1.0 ｜ 任务：[GOV-004](tasks/GOV-004.json) ｜ 2026-09-21 生效

适用范围：一切不经过 Git 的数据类交付——原始数据、清洗产物、特征产物、模型与评估产物。代码与文档的正常入库走 [COLLABORATION.md](COLLABORATION.md)；本规范把"交付"本身当接口管理：命名可辨识、结构可预期、内容可校验、接收有回执。

背景：2026-09-20 的两次硬盘交付暴露四类问题——交付包用裸主题名（如"特征工程"）无法辨识内容与版本；上游清洗数据整体混入下游工作目录一并拷贝；清洗脚本未随交付；交付报告的聚合计数与逐文件计数不一致，交付时无人对出。问题明细登记于受控对照页数据资产台账。

## 1. 交付包命名

```text
交付_<线代号>-<线名>_<内容与版本>_<YYYYMMDD>_<负责人>
```

示例：

- `交付_L1-数据清洗_契约v0.1-全量_20260920_娄澜`
- `交付_L2-特征工程_F0初版_20260920_周航正`
- `交付_L3-模型_E-B1折外_20261002_王健祺`

线代号与[总体执行路线图](plans/roadmap_overall.md) §2 一致：L1 数据清洗（娄澜）、L2 特征工程（周航正）、L3 模型（叶安＋王健祺）、L4 评估（吴钊同）、L5 评分（待定）。**禁止裸主题名**；同日同线多包在末尾加 `-2`、`-3`。

## 2. 顶层必备件（五件套，缺一不可）

| 件 | 要求 |
| --- | --- |
| `交付说明.md` | 内容清单；本包版本；源数据版本与上游依赖（写明依赖哪个交付包及其完整性清单指纹）；已知问题；消费入口（下游从哪张表读起） |
| `完整性清单.json` | 逐文件 md5、行数、字节数；生成后回读校验 |
| `校验报告.json` | 聚合计数 ＋ "聚合计数 ＝ 逐文件计数之和"断言结果 ＋ 守恒对账（输入 − 隔离 − 去重 ＝ 输出） |
| `scripts/` | 产出本包数据的全部脚本快照；已入库的标 git commit，未入库的标版本号并尽快补入库 |
| 正文目录 | 按 §3 各线结构组织 |

受控硬盘上的交付说明与报告可含真实统计；其中任何内容入公开仓库前按 [DATA_POLICY.md](DATA_POLICY.md) 脱敏。

## 3. 各线目录结构（权威模板）

**L1 数据清洗**（以 2026-09-20 已交付结构为基准正式化）：

```text
契约vX.Y全量/
  v0_interface/  v1_annotated/  v2_corrected/  v3_anomaly_marked/  v4_assessed/
  _agg/  辅助_*  隔离_*
```

传感流物理副本只存 v0/v1 两层；v2–v4 为表级差异，不复制大文件。

**L2 特征工程**：

```text
src/  config/  tests/  docs/
artifacts/
  imu_accident_features.csv ＋ .manifest.json
  model_interface/  model_input.csv ＋ feature_schema.json
  clustering/
```

**L3 模型**：

```text
src/  config/
artifacts/
  oof_predictions/（A/<成员>、B/<群>/<模型> 命名）
  model_score/  forecast_result/
run_manifest（feature_version / split_version / source_version / 种子 / git commit）
```

**L4 评估 / L5 评分**：代码入 Git；结果表随包带 split_version（L4）或规则版本（L5），结构随首个实际交付细化并回填本节。

**上游数据不随下游交付包重复拷贝**：交付说明声明依赖的上游包与版本；确需随包携带时单独打包、独立命名，不混入下游工作目录。

## 4. 接收与回执

接收方（消费线负责人或协调者）在首次消费前完成联合对数：

1. 完整性清单抽验——任选若干文件重算 md5；
2. 聚合计数 ＝ 逐文件计数之和；
3. 接口契约字段与不变量核对（见对应契约文档）。

对数不通过的包不得作为下游输入。回执记入消费任务的 evidence 与 worklog——公开仓库只记交付包名、版本与证据编号；数值结论入受控对照页。

## 5. 脚本与产物的归属

- 处理数据的脚本属于代码：脱敏复核后入 Git，不在"受控本地维护"状态长期滞留；交付包内 `scripts/` 是运行时快照，与仓库登记版本对应。
- 数据产物不入公开仓库；位置、版本与指纹记入受控对照页"数据资产台账"。
